# 世界区块、敌人生成与寻路：详细底层规格

## A. 三套坐标与实体注册表
- GlobalPosition：`Vector3`，X/Z水平、Y垂直，坐标允许负数；世界坐标不要随场景节点原点重置。如果需要浮点原点漂移，逻辑坐标保留double/64-bit区块整数+局部位置。
- ChunkKey：`floor(position.x/64),floor(position.z/64)`；同区块里的地形与动态对象分别管理；建筑房间有`building_id/floor_id/room_id`。
- PopulationKey：区域/生态/世界层/组ID；物理敌人实例`entity_id`在整个存档生命周期唯一，不依赖当前加载的NodePath。

### A1. WorldRegistry应当保存哪些信息
`entity_id,definition_id,world_layer,chunk_id,transform,owner_container_id,lifecycle,revision,last_simulated_tick`。
生命周期分成`active_scene`,`hibernating_record`,`dead_saved`,`deleted_committed`。千万不要用“场景节点消失了”推断世界实体已删除。

## B. 四级地图数据LOD
| 级别 | 距离建议 | 实际数据 | 保留内容 |
|---|---:|---|---|
| L0 | 0-70m | 地形、碰撞、门窗、NPC完整节点 | 战斗/搜刮/AI完整交互 |
| L1 | 70-200m | 地形低模、道路碰撞、少量动态Node | 驾驶、远距枪声/尸群迁移 |
| L2 | 200-450m | 视觉地形和道路占位 | 预取方向/远景遮挡 |
| L3 | >450m | 纯chunk metadata | 人口池、世界计时、建筑改造快照 |

距离为首轮建议。车辆驾驶增加前向碰撞区预取；远方可见高楼、山地、水体等可选独立低多边形远景批次，不随每个区块创建无数MeshInstance3D。

### B1. Chunk状态机与异步回调
```
UNLOADED -> REQUESTED -> DATA_READY -> INSTANTIATING -> ACTIVE
                                                 |
ACTIVE -> COOLING -> SERIALIZING -> (save ack) -> UNLOADED
  ^                       |
  +-----------------------+  (玩家返回，取消旧卸载；先重验请求token)
```
所有数据读取和后台生成必须带`generation_token`。当旧请求完成但新位置早已离开该区块时丢弃结果；不能使用旧数据覆盖新revision。

### B2. CPU帧预算
- `chunk_manifest_read_budget_ms`: 推荐2ms平均；资源已缓存时可减少。
- `node_instantiate_budget_ms`: 推荐2—5ms每帧；优先道路/地形碰撞、然后可交互建筑，再装饰物件。
- `path_query_budget_ms`: 推荐1.5—3ms每物理帧（需按机器实测）。
- `enemy_activation_count`: 推荐≤4个/调度tick，且每区块活跃≤18个，允许剧情战斗临时覆盖并登记原因。
- 若性能超预算，先降低次要LOD与 AI 物理频率，**不丢弃存档状态、不让敌人瞬移到视野内**。

## C. 生成调度核心公式（设计方案，不是《僵毁》真实源码）
1. 基线人口：`base_population = floor(zone_density × habitable_area_m2 × 0.004 × world_difficulty)`；再按住宅/商业/医院配置随机源，seed稳定。
2. 激活名额：`allow = min(zone_alive_hibernating, global_active_cap - global_active, chunk_active_cap - chunk_active, activation_budget)`。
3. 候选分数：`w = zone_weight × anchor_type_weight × (1 - player_visibility) × nav_valid × (1 - safehouse_protection) × weather_activity_modifier`。
4. 不依赖“玩家进区块”反复生成新敌人；刷新策略需消费可再生人口池的明确凭证、冷却与日志。首次房间触发使用 `visited_room_id` 不会再次创建基础人口。
5. 每一次激活记录 `population_cell_id,enemy_id,anchor_id,world_tick,reason`；每次死亡写死者ID并生成唯一尸体ID。

### C1. 生成不能做的事情
- 在玩家正在看的窗台后面直接创建丧尸。
- 敌人破门进入后玩家离开区块，重新进入又把已死敌人复活。
- 两个区块同时对同一组移动尸群各自实例化一次。
- 主世界与颠倒世界共享同一个“生成丧尸”权重表（颠倒世界不生成丧尸）。

### C2. 远处迁移和枪声
远程枪声产生SoundEvent并记录于声学区域，人口池迁移以“群体 token”转移。群体成员的个体ID保留，目标向最近声源区块粗路径推进。到达玩家附近后，拆成可见独立敌人Node。离开又合并时，成员ID仍相同。雨雾可以影响丧尸远程听觉，但克苏鲁默认不响应普通声源。

## D. 寻路分层图的数据结构
```
WorldChunkGraph
├── Chunk [PortalNode, NeighborChunkId]
│   ├── RoadPortal (east/west/north/south)
│   ├── BuildingEntrancePortal
│   ├── StairPortal (from_floor,to_floor)
│   ├── WindowVaultPortal (abilities_required)
│   └── VehicleRoadPortal (vehicle_nav_cost)
└── LocalNavigationMap[MAIN_WORLD / INVERTED_WORLD]
    ├── TerrainNavRegions
    ├── BuildingFloorNavRegions
    └── DynamicLinkRegistry
```
粗图A*的启发式是两门户X/Z距离×基础步行成本（避免不可采纳的过高估价）；每条边记录`distance,climb_cost,door_state,threat_bias,required_action,revision`。AI的行动能力不同会影响是否可通行，普通丧尸能破普通木门、不能穿越加锁钢门；玩家可以开门或翻窗。状态改变时，只使关联边失效而不是重建全世界NavMesh。

### D1. 走门、走楼梯、翻窗的具体流程
1. 在世界粗路径上选中下一个Portal，查询静态通行资格。
2. 如果Portal是关闭的门，AI依据能力选择`OPEN`, `BASH`, `BREAK_GLASS`, `WAIT`或`REROUTE`。
3. 靠近门前排队锚点，避免多个CharacterBody3D在门口互相顶住。
4. 破门成功时只改`door_id.open_state`与局部NavPortal边，触发EventBus。
5. 若是楼梯，读取目标楼层NavRegion，沿真实坡/踏步NavMesh前进。NPC自然跟随玩家，不整体同步传送。
6. 若出口拥堵，NPC排队、侧让或临时选择另一DoorPortal；路径卡住记录stuck事件供调试。

### D2. Navmesh修改
挖矿/建墙/拆门/倒树后标记影响的局部tile块`nav_dirty=true`，在预算内重新构建局部可导航几何。导航查询在更新窗口要标记NavRegion未同步，AI保持当前位置安全移动或采用原路径局部避障，不允许瞬移。Godot的NavigationServer更改通常下一物理帧生效；异步烘焙完成必须再等服务器同步确认。

### D3. 追击时间与重规划
- 视线确认期0.2—0.5s，失视记住最后位置8—15s，搜索6—12s（首轮参数）。
- 目标移动超过重规划阈值或连续0.5—0.8s才重算路径；每物理帧仍调用`get_next_path_position()`更新已有路径。
- T3/T4克苏鲁持续视线提升仇恨、速度；掩体失视后降速但继续追踪最后位置，搜索失败后逐渐衰减并回领地。
- 人类NPC随行重视“队友出口拥堵”和安全偏移，不使用与丧尸完全相同的紧贴目标轨迹。

## E. 故障恢复与存档
区块卸载必须先：冻结本区新实体激活→把活跃敌人转换为hibernating记录→写实体快照和人口池→确认写盘→从场景树移除Node。若写盘失败保留激活数据并重试，绝不能释放唯一存在的状态。读档时先恢复共享世界物体，再恢复当前世界层敌人集合；未完成的裂隙车辆转移先检查WAL，回滚或幂等完成一次。

## F. 必须实际跑的压力测试
- 负X/Z区块边界，连续跑/开车经过(-64,0),(0,-64),(-128,-128)。
- 200只城市敌人，其中近处60只完整AI，其余低频/群组；查看p95帧耗时。
- 10次进出医院一层和二层，已死敌人/掉落/破门状态保持。
- 门已关闭、破坏、上锁三种状态的寻路对比。
- 玩家在三次开关背包/医疗面板期间疾跑，丧尸攻击仍触发。
- 同一矿洞在主世界挖通，颠倒世界结构同步但敌人生态不同。
- 高等级裂隙把车辆+2位NPC+后备箱转层，读档后所有ID只出现一次。
