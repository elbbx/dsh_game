# M08｜敌人人口池、激活、迁徙与尸潮——独立可执行设计书

> **定位：**本文件先给本模块的完整可执行设计与对应数据，再附106章原规划中属于本模块的条款。表中数值为初始游戏平衡配置，非已测试结论。

## 1. 玩家体验与系统边界

区块人口和实例集合分开，视野保护、冷却、尸群迁移、声源诱导。本模块不得绕过物品所有权、世界层身份、世界时钟和全局事件幂等机制。

## 2. 完整业务处理链

1. **种子生成区域人口预算**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
2. **近区选择可视安全的合法锚点**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
3. **按唯一ID激活EnemyInstance**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
4. **群体向声源与道路迁移**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
5. **卸载后压缩成摘要但保持死亡记录**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。

## 3. 模块专属规则、数值逻辑与边界

### 人口池三种守恒
每区维护 `initial_population/active_ids/dormant_groups/dead_ids`；逻辑居民人数总量通过出生/跨区流入/跨区流出/死亡操作审计。激活上限是性能预算，不是“可以任意随机增殖”。一次声源生成迁移命令，群体拥有唯一group_id；迁移到新块只转移归属、不能重新随机roll人数。出入建筑或游戏读档不会重置已死亡实体。

## 敌人生成底层详细策略
**地图级分布**：每个区块建立 `PopulationCell`，包含基础密度、当前活动数、休眠数、区域累计击杀、迁徙流量、玩家热度、冷却时钟和安全区遮罩。以居民区/商业区/医院/森林配置不同权重。世界生成时先落盘群体人口ID，运行期间只有“被动迁移/合理补充”能够改变人口池。
**生成请求**：生成器先比较人口上限与`global_active_cap`、`chunk_active_cap`，再检测视野、摄像机近裁、玩家距离、建筑门窗可达性、地形障碍、导航有效性和近期清理保护。不能直接以“玩家离开又返回”作为重生条件。
**三级生态**：近处 < 70m 使用完整AI和物理；中程70–220m 使用低频AI和简化路径；超过220m由人口池记录队伍/方向/目标更新时间，不持有Node。数值为首轮建议，允许车辆速度与硬件动态调整。
**建筑内部**：初次进入建筑触发房间锚点激活，但实例ID与生成种子必须保持稳定；柜台/门后/卧室可潜伏；不可从玩家视线中的房间凭空出现。
**尸潮**：枪声向人口池添加迁移目标；越过区块线将群体ID转让给新PopulationCell；队伍解散成个体后不重复增加总人口。
**死亡与掉落**：原子操作标记死者实例、扣人口、生成尸体与战利品、发送音效；读档后只能出现一次。
**安全**：在载具高速移动、装载延迟、双世界切换期间暂停“新实体激活”，不是暂停世界；继续统计人口和目标流向。

# 9. 丧尸类型、感知与尸潮

## 9.1 丧尸定位

丧尸是世界中数量最多的常规威胁。危险来自数量、声音、追逐、包围和持续消耗。

## 9.2 感知系统

  感知   机制
  ------ --------------------------------------
  视觉   根据距离、视野和遮挡发现玩家
  听觉   根据声音强度、距离和环境遮挡判断位置
  嗅觉   少数特殊丧尸追踪血液或气味

声音系统需要考虑墙壁、门窗、楼层和环境遮挡。

## 9.3 丧尸 AI 状态机

基础状态：

1.  游荡：随机移动、站立和徘徊。
2.  调查：发现声音后前往声音来源。
3.  发现目标：视觉或其他感知确认玩家。
4.  追逐：寻找路径并接近玩家。
5.  攻击：抓取、撕咬或攻击。
6.  搜索：失去目标后前往最后发现位置并搜索。
7.  恢复游荡：搜索失败后返回游荡。

丧尸失去视线后记录玩家最后出现位置，并前往该位置搜索。

## 9.4 丧尸能力

-   进入普通房屋。
-   撞击房门。
-   破坏部分门窗。
-   翻越低矮障碍。
-   使用楼梯在建筑内部移动。
-   聚集并挤压入口。
-   在建筑内部搜索玩家。

## 9.5 第一批丧尸种类

  类型       核心机制
  ---------- --------------------------------
  普通丧尸   行动缓慢，数量多，群体威胁高
  奔跑者     速度快，擅长追击
  爬行者     隐藏在家具、桌下和车辆附近
  膨胀丧尸   可能释放污染液体
  装甲丧尸   正面防护高，需要攻击暴露部位
  尖叫者     发现玩家后发出声音吸引附近尸群

普通丧尸必须占据绝大多数。特殊丧尸只在特定区域或事件中出现。

## 9.6 尸潮

尸潮采用动态模拟：

-   城镇、住宅区、医院和商业区有不同基础分布。
-   枪声、爆炸和警报吸引附近尸群。
-   尸群可以从多个方向向声音来源移动。
-   部分尸群在没有玩家干扰时缓慢迁徙。
-   尸群可以堵塞道路和建筑入口。
-   大量丧尸可以破坏外围防御设施。

玩家在超市搜刮时触发汽车警报，应当能够形成"继续搜刮、从后门撤离、丢弃物资、绕路或战斗"的选择。

# 12. 敌人刷新与世界生态

## 12.1 刷新原则

克苏鲁敌人刷新根据以下参数综合计算：

-   当前异常关注度。
-   最高解锁遭遇阶段。
-   当前区域污染等级。
-   昼夜和环境亮度。
-   区域刷新点类型。
-   当前区域活跃敌人数量。
-   玩家与刷新点的距离。
-   最近一次遭遇时间。
-   当前任务和特殊事件。

## 12.2 各级敌人刷新

  ---------------------------------------------------------------------------------------
  类型          主要区域                           刷新规则
  ------------- ---------------------------------- --------------------------------------
  T1            居民区边缘、森林、废弃建筑         可在较低关注度出现，数量相对多

  T2            建筑内部、地下室、低中污染区       关注度达到阶段1后提高概率

  T3            中高污染区、医院和研究设施         关注度达到阶段2后出现

  T4            高污染区、特殊地点外围             关注度达到阶段3后出现

  T5            固定遗迹、地下祭坛、核心实验设施   通过固定地点、调查进度或特殊事件触发
  ---------------------------------------------------------------------------------------

## 12.3 刷新保护规则

-   刷新锚点布置在玩家视野外，并结合遮挡、距离和环境预兆进行判定。
-   每类敌人设置最小生成距离和有效刷新范围。
-   高级敌人只在匹配的污染区域出现。
-   同一区域设置高级敌人数量上限。
-   同类遭遇设置刷新冷却。
-   T4出现前提供环境预兆。
-   安全据点使用独立刷新配置，敌人活动由据点防御和特殊事件控制。
-   T5只通过固定地点、任务或特殊事件触发。

## 12.4 环境预兆

高级敌人出现前可以出现：

-   远处短暂黑色轮廓。
-   环境光线异常。
-   无线电信号变化。
-   建筑内部不合理的阴影。
-   SAN短暂波动。
-   异常声音或空间视觉变化。

环境预兆采用多套表现组合，并根据区域与敌人类型变化；预兆提供威胁等级和方向线索。

## 12.5 丧尸与克苏鲁互动

  交互                           结果
  ------------------------------ ------------------------------------------------------------
  丧尸发现玩家                   追逐玩家
  丧尸发现可攻击克苏鲁           根据距离和攻击规则决定是否攻击
  敌对克苏鲁发现丧尸             可以攻击丧尸
  敌对克苏鲁发现玩家             满足感知与攻击条件后攻击
  T1发现玩家                     通过观察行为施加SAN压力
  玩家开枪                       声音事件由丧尸听觉系统响应，克苏鲁按视觉与特殊感知规则行动
  玩家照射具备光源感知的克苏鲁   可能触发光源仇恨

不同克苏鲁对丧尸的态度可以不同：捕食、驱赶、寄生、控制或忽略。

# 17. 数据结构、存档与性能要求

## 17.1 技能数据

建议使用独立 Resource 保存技能定义：

``` gdscript
class_name SkillData
extends Resource

@export var skill_id: String
@export var skill_name: String
@export var max_level: int = 25
@export var per_level_benefits: Array[Resource] = []  # 25条静态能力配置

# SkillProgress（独立运行态）存储base_level与current_xp；
# 不将每位玩家的进度写进共享的SkillData资源。
```

技能静态定义、技能当前等级经验、逐级能力与图纸/任务获得的配方知识应分开管理；逐级能力可依据基础等级重新计算。

## 17.2 食物数据

``` gdscript
class_name FoodData
extends Resource

@export var food_id: String
@export var food_name: String
@export var calories: float
@export var satiety: float
@export var weight: float
@export var inventory_size: Vector2i
```

## 17.3 体型数据

``` gdscript
class_name BodyCondition
extends Resource

@export_range(-25, 25) var modifier: int = 0
@export var calorie_balance_bank: float = 0.0

func get_effective_strength(base_level: int) -> int:
    return base_level + modifier

func get_effective_agility(base_level: int) -> int:
    return base_level - modifier
```

正式项目中，体型变化的累计热量余额、基础技能等级和有效等级应分开保存。有效等级在读取时重新计算，避免存档数据不一致。

## 17.4 敌人刷新架构

``` text
AnomalyManager
├── AnomalyAttention
├── HighestEncounterStage
├── SpawnPointDatabase
├── SpawnDirector
├── SpawnCooldown
├── ActiveCreatureLimit
└── RegionPollution
```

## 17.5 存档内容

至少保存：

-   玩家位置、朝向和世界时间。
-   七项生存状态。
-   身体部位伤势和疾病。
-   十种技能基础等级与经验。
-   逐级能力与配方永久解锁状态（由基础等级推导，并保留图纸/任务来源）。
-   当前背包、容器和装备。
-   物品耐久、弹匣和弹药状态。
-   当前热量累计余额。
-   当前体型修正。
-   SAN。
-   异常关注度。
-   最高遭遇阶段。
-   区域污染和世界事件状态。
-   已探索建筑和已搜刮容器状态。
-   据点设施和储物内容。

## 17.5A 存档字段定义
保存字段包括感染值与感染暴露记录、抗感染药物持续效果、电力技能经验、武器本体实例与全部配件实例、车辆/零件/油量/车内货物/座位与活跃世界层、车辆裂隙事件、天气种子/区域状态/预测时间、湿润状态、建造和家具实例与结构完整度、NPC身份/岗位/任务进度、发电机燃料和耐久、太阳能板状态、锂电池储电、各中继器和线缆连接的图ID、负载优先级和当前电网结算时间。共享场景物件不得按世界层各存两份。

## 17.6 大地图性能

地图敌人根据距离采用完整AI、简化AI和区域统计三级模拟。

建议三级模拟：

  距离     模拟方式
  -------- ----------------------------------
  近距离   完整AI、寻路、感知、攻击和动画
  中距离   简化移动和低频状态更新
  远距离   区域尸群数量、迁徙和简化事件模拟

建筑内部、楼层和外部空间的寻路连接需要统一管理，避免敌人进入建筑后无法正确上下楼。

# 29. 裂隙、敌人与异常关注度的联动

## 29.1 三种独立参数

需要区分：

  参数           作用
  -------------- --------------------------
  SAN            玩家当前精神稳定程度
  异常关注度     异常世界对玩家的关注程度
  区域污染等级   当前区域的异常强度

三者分别保存，并通过明确的联动规则共同影响敌人刷新和裂隙生成。

## 29.2 裂隙生成权重

建议：

-   SAN越低，精神异常压力越高，裂隙候选点权重越高。
-   异常关注度越高，裂隙生成概率越高。
-   区域污染等级越高，裂隙更容易生成。
-   玩家在同一地区停留越久，候选地块权重可以逐渐增加。
-   已经生成裂隙的区域进入冷却，避免短时间连续生成。

## 29.3 颠倒世界敌人刷新

颠倒世界的克苏鲁刷新由以下因素决定：

-   当前区域污染等级。
-   当前异常关注度。
-   最高遭遇阶段。
-   玩家在颠倒世界停留时间。
-   当前区域的敌人数量。
-   固定型和区域型敌人的占位情况。
-   是否存在特殊剧情事件。

颠倒世界敌人密度根据区域等级、当前敌人数量、刷新冷却和玩家停留时间动态计算。

## 29.4 玩家停留时间

颠倒世界可以增加一个隐藏的 `InvertedExposureTime`：

-   用于控制特殊事件出现概率。
-   用于调整异常环境效果。
-   用于触发部分裂隙不稳定事件。
-   用于提高高等级克苏鲁的遭遇概率。

InvertedExposureTime作为独立世界层参数，控制特殊事件、环境变化和遭遇权重；SAN仍单独计算。

## 29.5 裂隙与敌人的关系

建议增加以下规则：

-   部分固定型克苏鲁守护裂隙。
-   部分区域型克苏鲁以裂隙为领地中心。
-   T4刷新点在区域内分散布置，并依据出口安全距离进行配置。
-   T5可以控制某个区域的裂隙开合。
-   跨越裂隙的克苏鲁通过专属跨界能力和特殊事件配置实现。
-   特殊剧情敌人可以拥有跨世界能力，但必须作为独立能力设计。

## 29.6 进入颠倒世界的风险递增

建议玩家在颠倒世界停留越久，环境压力越明显，但必须给出可读的预兆：

1.  初期：环境异响、远处轮廓和低频SAN压力。
2.  中期：异常生物活动增加，裂隙位置出现变化。
3.  后期：高等级克苏鲁巡猎，部分区域出现空间干扰。
4.  极端状态：特殊事件触发，玩家需要尽快寻找出口。

颠倒世界停留时间通过环境压力、敌人活动和裂隙状态逐步提高探索风险，让玩家根据路线和资源判断继续深入的时机。

# 33. 双世界与高级AI验收标准

## 33.1 双世界同步

-   两个世界使用相同建筑坐标和房间布局。
-   玩家在一个世界打开门，另一个世界对应门保持打开。
-   玩家在一个世界打碎窗户，另一个世界对应窗户保持破碎。
-   玩家在一个世界搜刮容器，另一个世界容器同步为空。
-   玩家在一个世界拾取物资后，另一个世界对应位置同步显示已拾取状态。
-   玩家在一个世界丢弃物品，另一世界对应位置能看到同一物品。
-   玩家切换世界后，背包、HP、SAN、伤势和世界时间保持当前状态。

## 33.2 颠倒世界生态

-   颠倒世界生态层由克苏鲁生物组成。
-   主世界丧尸保留在主世界生态层，颠倒世界运行克苏鲁生态层。
-   颠倒世界能够刷新T1--T4克苏鲁。
-   T5只通过特殊地点或事件出现。
-   颠倒世界敌人使用独立实例ID和世界层存档，返回主世界时恢复原有实例状态。
-   主世界和颠倒世界的敌人状态能够独立保存。

## 33.3 裂隙系统

-   SAN或异常关注度达到条件时可以触发裂隙候选地块。
-   高污染区域可以提高裂隙生成权重。
-   裂隙候选点经过玩家距离、地形状态和环境预兆检查后生成。
-   裂隙出现前具有环境预兆。
-   触手抓取路径通过墙体和大型障碍遮挡检测。
-   裂隙具有抓取冷却和区域数量限制。
-   玩家能够通过对应裂隙返回。
-   出口失效时有备用返回机制。
-   存档读档后根据裂隙配对ID恢复入口、出口和备用锚点。

## 33.4 仇恨追踪

-   持续可见时仇恨增长速度递增。
-   仇恨值提高时移动速度提高。
-   失去视线后移动速度下降。
-   失去视线后敌人前往最后发现位置。
-   敌人使用最后发现位置和搜索系统更新目标。
-   到达最后位置后会进行搜索。
-   搜索失败后仇恨逐渐衰减。
-   玩家重新进入视线后敌人重新追踪。
-   光源感知能够使用同一套仇恨系统。
-   仇恨通过记忆时长、搜索时间和衰减速率回落。

## 33.5 固定和区域型敌人

-   固定型敌人主体持续锚定在指定位置。
-   固定型敌人可以通过触手和区域攻击威胁玩家。
-   固定型敌人的仇恨提高攻击频率、触手伸展速度和攻击范围。
-   区域型敌人能够在领地内部巡逻和追击。
-   区域型敌人按照领地边界管理追击和返回行为。
-   玩家离开领地后，敌人会停止扩大追击范围。
-   潜伏型敌人具有可观察的环境预兆。
