## 1. 玩家体验与系统边界

衣物分层影响体温湿度、舒适与行动；伤口感染与病毒性感冒分开。本模块不得绕过物品所有权、世界层身份、世界时钟和全局事件幂等机制。

## 3. 模块专属规则、数值逻辑与边界

### 衣物卫生与环境病
衣物属性保暖/防雨/防风/透气/抓咬防御/弹道防御分开；穿着层级决定湿润和散热。角色皮肤湿度与衣物湿度各自保存，脱湿衣不瞬间清除身上的汗。洗手洗澡耗水及清洁剂；洗衣、晾晒和电动烘干各自耗时与能源。感冒按隐藏风险暴露模拟，病毒性感冒不能通过洗澡或普通抗生素“直接治愈”；丧尸感染更不能靠洗澡清除。

# 57. 衣物、盔甲与个人卫生：总设计

## 57.1 设计定位

衣物与卫生系统建立在第3章七项生存状态、第4章七部位伤害、第5章十技能、第7章网格背包、第43章天气和第44章感染机制之上。参考《僵尸毁灭工程》的**衣物分层、保温、防水、局部抓咬防护、沾血污、洗涤与环境疾病体验**，但将计算复杂度收敛到单人3D开放世界所需的可解释规则。所有数值是**第一轮游戏平衡参数**，不是现实医疗或服装试验数据。

目标是创造“出门选衣—天气变化—体感与战斗变化—衣服脏湿破损—回家清洁修补—恢复再出发”的可玩循环。

**系统约束：**

- HUD仍只显示HP、饥饿、口渴、疲劳、SAN、体力、丧尸感染七项；**体温、湿润、卫生与疾病**属于二级状态，通过图标和角色详情查看。
- 七个身体受击区继续为头、胸、腹、左右臂、左右腿；衣物可按更细的装备覆盖区计算，最终映射至七大伤害区域。
- 十种技能总数不变。不设独立“裁缝”或“卫生”技能；修补由**制作**，伤口与疾病由**医疗**，野外保暖与清洁材料由**生存**，洗衣设备电路由**电力**，机器维护由**机械**负责。
- 第44章 `ZombieInfection` 只由丧尸的有效感染暴露与对应治疗改变；`WoundInfection` 为局部伤口感染；`ColdSeverity` 等环境疾病另存，绝不互相混用。
- 《僵尸毁灭工程》的参考点是**系统类型与体验**，下述概率、配方、AI联动和电力数字均是本项目自行设计，不宣称是原作精确公式。

## 57.2 系统拓扑

```text
WeatherState / WorldClock / RoomShelter
        ↓
LocalExposure（温度、风寒、降雨、日晒、屋顶、室内热源）
        ├─ ClothingSystem（各件衣物：材质、覆盖、防水、湿度、耐久、污渍）
        ├─ Thermoregulation（皮肤湿度、汗液、热压力、低体温/过热）
        └─ EnvironmentalIllness（感冒、污水食物病、尸体污染症状）
                     ↓
PlayerStatusModifier（对七项核心状态产生受控的修正）

CombatHit → 受击部位 → 外层到内层的护甲防护/磨损 → HP与局部伤势
                                                   └─ ZombieInfection有效暴露
HygieneAction → 消耗水/肥皂/时间 → 清除皮肤与衣物污渍、降低局部伤口污染风险
WashingMachine / Dryer → 读取既有 PowerGridManager，不新增电力节点类别
```

## 57.3 不可混淆的独立变量

| 数据 | 范围或类型 | 代表含义 | 是否占据主HUD |
|---|---|---|---|
| `skin_wetness` | 0—100 | 角色皮肤表面潮湿程度 | 否 |
| `clothing_wetness[item]` | 0—100 | 每件衣物各自含水程度 | 否 |
| `thermal_stress` | -100—100 | 负值偏冷，正值偏热，使用第43章的定义 | 否 |
| `body_dirt` / `body_blood` / `sweat` | 0—100 | 个人清洁、污染与汗液 | 否 |
| `clothing_dirt` / `clothing_blood` | 0—100 | 每件衣物独立污渍 | 否 |
| `cold_severity` | 0—100 | 感冒及呼吸道不适强度 | 否 |
| `environmental_illness` | 多状态字典 | 食物中毒、腐败气味暴露、其他疾病 | 否 |
| `ZombieInfection` | 0—100 | 第44章可治疗的丧尸感染 | **是** |
| `WoundInfection` | 每伤口状态 | 细菌性伤口感染 | 否，显示于部位面板 |

角色级 `wetness` 是供HUD和状态系统读取的**聚合派生值**，由皮肤与已穿着衣物湿度生成，不允许天气、洗澡和游泳三个系统分别直接写这个值。第43章的湿润提示使用该派生值，湿衣品的干燥另按单件存档。

## 57.4 体验约束

- 玩家在轻度脏污下可以正常行动；卫生不会变成每五分钟强制清洁一次的琐碎劳动。
- 只在**湿冷持续暴露、明显过热、高污物叠加开放伤口**等情况下产生实质负面效果。
- 有些装甲在防丧尸时更强，但散热差、重量高；有些雨衣挡雨但咬伤防御低；应存在有意义的选择，没有一件万能衣服。
- 淋雨不会平白产生丧尸病毒；天气影响的疾病风险、伤口恢复能力与第44章感染进展分别结算。
- 不引入因为“没洗澡一天”就突然大幅掉HP或SAN的惩罚。

# 58. 衣物分层、材质、体型与防护规格

## 58.1 服装层级及槽位

角色模型以已有装备部位为基础，建议一件衣物最多占用一个**主装备槽**，并声明覆盖的身体区域，允许不同层共存：

| 分层 | 典型槽位 | 典型物品 | 主要用途 |
|---|---|---|---|
| 基础内层 | 内衣、袜子、贴身上衣 | T恤、内衣、保暖内衣 | 吸汗、基础保温、舒适度 |
| 日常层 | 上衣、裤子 | 衬衫、牛仔裤、工装裤 | 轻度防护、口袋、温控 |
| 保暖层 | 毛衣、抓绒、棉服内胆 | 毛衣、卫衣、绒裤 | 提高保温但增加热负荷 |
| 外壳层 | 外套/防雨外壳 | 雨衣、风衣、冲锋衣 | 防雨、防风、遮挡血污 |
| 防护层 | 胸甲、护肩、护臂、护膝 | 防弹背心、护臂、护腿 | 抗咬、抗抓、抗弹道/异常 |
| 配饰层 | 手套、围巾、帽、面罩、鞋靴 | 冬帽、围巾、胶靴 | 局部覆盖、耐候与特殊保护 |
| 携行层 | 腰带、战术背心、背包 | 装具、包袋 | 影响容器容量与重量，不自动叠为厚衣 |

**层级冲突规则：**

1. 同层互斥，例如厚外套与全封闭雨衣占同一外壳槽；短雨披可使用例外兼容标签。
2. 全封闭重甲可以占用外壳槽与护甲槽，装备前UI说明将自动卸下的物品。
3. 每件装备具有 `coverage_mask`（头、颈、胸、腹、上臂、前臂、手、腿、脚），伤害最终仍映射七部位。
4. 穿上、脱下物品需要短动作时间；奔跑/战斗中操作受限制，不直接瞬间全身换装。
5. 体型变化沿用第6章Blend Shape/模型档位；服装按照已有体型参数适配，不另开尺寸不合惩罚。

## 58.2 衣物静态属性与实例属性

静态 `ClothingData`：

- `item_id`、`garment_type`、`layer`、`compatible_tags`、`coverage_mask`；
- `material`（棉、羊毛、牛仔布、皮革、合成纤维、橡胶、防护复材、金属）；
- `insulation`（0—100）、`wind_resistance`（0—100）、`water_resistance`（0—100）、`breathability`（0—100）；
- `scratch_defense`、`bite_defense`、`ballistic_defense`、`abnormal_resistance`（分开配置）；
- `dry_weight_kg`、`wet_weight_capacity_kg`、`durability_max`、`pocket_grid`、`noise_modifier`、`movement_penalty`；
- `appearance_glb`、材质表、破损材质槽及修补类型。

实例 `ClothingInstance`：

- `instance_id`、`condition`、`wearer_id`、`wetness`、`dirt`、`blood`、`odor`；
- `damage_by_region`、`patches_by_region`、`last_condition_update_minute`、`last_dry_update_minute`；
- `is_equipped`、`is_washing`、`is_drying`、`storage_container_id`。

同一种物品的两个实例可以一件干净耐用、一件沾血破洞；实例间不可共用耐久或污渍。

## 58.5 防护结算与层级

每次命中先确定具体部位和攻击类型，然后按**外→内**读取覆盖该部位的衣物与盔甲，执行“覆盖判定、减伤/拦截、装备耐久损失、残余伤害、局部伤口、丧尸感染暴露”的顺序。

初步可使用软叠加：

```text
有效单件防护 p_i = 原防护值/100 × 当前完整系数 × 局部覆盖系数 × 攻击类型系数
综合防护 P = clamp(1 - ∏(1 - p_i), 0, 防护上限)
伤害剩余系数 = 1 - P
```

**重要：** 防弹防护与抗咬是不同数据，且完整格挡必须由攻击命中结果明确返回 `blocked=true`，才允许第44章认定本次丧尸感染暴露为零；`P` 不能直接被当作感染抵抗率。非完整格挡按残余穿透和服装密闭性减小感染剂量。

建议普通服装抗咬综合防护上限85%，专用重甲可以突破常规上限但必须承担重量、散热、维护成本。局部破洞按该部位完整系数降低防护，不会导致未破损的其他部位整件失效。

## 58.6 穿着与移动、射击、声音

- 重装：移动、翻越、近战挥击与体力恢复受影响，与第7章总负重倍率合成时设置上限，避免重复惩罚。
- 宽松/金属装备：行走摩擦声增大，向**丧尸声音系统**发送正常声音事件；无普通听觉的克苏鲁不接收衣物摩擦声。
- 全封闭护目镜、面罩：可选略减视角和观察清晰度，但不得强行破坏45°斜视角的可玩性。
- 穿潮湿靴子：脚步声材质变化；湿靴重且脚部干燥慢。
- 护甲清洗：可拆护甲板与织物载体分开处理，避免“整块金属甲丢进洗衣机”。

# 59. 体温、出汗、风寒和衣物湿润

## 59.1 感知量和结算量

继续使用第43章天气字段 `air_temperature`、`wind_vector`、`precipitation_rate`、`ambient_light`、`ground_wetness`，增加局部 `shelter_ratio`、`sun_exposure`、`nearby_heat_source`、`water_contact` 和 `room_temperature_modifier`。

玩家不需要真实生理模拟，用**冷热压力**表达：`thermal_stress` 从-100（极度偏冷）到+100（极度偏热），0为舒适。UI只展示“舒适、微冷、寒冷、失温风险、微热、过热、中暑风险”。

基础结算步骤（每1个游戏分钟或累计等效时间）：

1. 读取当前局部温度、风、雨和房屋遮蔽/热源。
2. 汇总各部位服装的有效保暖、防风、透气、覆盖度与当前湿润。
3. 依据行走、奔跑、近战、搬运和感染发热增加产热与出汗。
4. 降雨/水接触湿润外层；汗液从皮肤向内层转移，饱和后传至外层。
5. 计算湿布蒸发、风寒和日晒的冷/热压力。
6. 更新 `thermal_stress`，再由阶段产生七项状态修正。
7. 更新角色级的聚合湿度与状态提示。

## 59.2 防护和透气的实际效果

**有效保暖**因衣服潮湿降低：

```text
effective_insulation = dry_insulation × (1 - wetness/100 × material_wet_penalty)
```

`material_wet_penalty` 是材质系数，初始可设棉0.70、羊毛0.30、合成保暖层0.45、防水外壳0.20。外壳抗水不代表完全不吸汗，连续活动的汗液仍由内部透气能力决定。

**降雨湿润**按从外到内传递：外层 `water_resistance`越高，内层湿润越慢；有破洞时相应部位的挡水失效。游泳/涉深水可直接浸湿各层，不受雨衣防雨系数完整阻挡。

**出汗**在高体力消耗或热压力下出现，最先提高 `skin_wetness` 与贴身层湿度。持续穿防水雨衣奔跑容易“外面没湿、里面汗湿”，对应有意义的雨天换装选择。

## 59.3 冷热阶段与惩罚上限

| `thermal_stress` | 状态 | 初始玩法影响 |
|---:|---|---|
| -19—+19 | 舒适 | 无惩罚 |
| -20—-39 | 微冷 | 体力恢复-3% |
| -40—-69 | 寒冷 | 体力恢复-8%，轻微动作效率下降 |
| -70—-89 | 严重寒冷 | 体力恢复-15%，疲劳增长+10% |
| -90—-100 | 失温风险 | 可在持续暴露后形成环境伤害，优先提示撤离 |
| +20—+39 | 微热 | 口渴增长+5% |
| +40—+69 | 过热 | 口渴增长+12%，体力消耗+8% |
| +70—+89 | 严重过热 | 疲劳增长+15%，运动效率下降 |
| +90—+100 | 中暑风险 | 持续高热可能造成环境伤害，需补水、阴凉、休息 |

轻、中度冷热不立即扣HP，严重阶段只有在**连续超时**且无法解除时才造成缓慢环境伤害；由独立 `exposure_duration` 累计，避免跨越阈值瞬间死亡。角色倒地危险状态必须有明确音效、文字与倒计时提示。

## 59.4 天气例子

- **夏季32℃、晴、穿重型防弹衣冲刺**：热压力升高、汗浸内层、口渴加速；卸掉厚外套、喝水、停下休息可恢复。
- **秋季10℃、小雨、穿棉T恤**：外层与皮肤逐渐湿润，风吹后转冷；雨衣+薄保暖层优于单纯穿厚棉衣。
- **冬季-2℃、积雪、穿毛衣+防风壳**：可维持体温，但靴子浸水和缺乏手套会使局部热舒适变差。
- **雨停后室内**：外层可脱下挂晾，皮肤湿度先消退，衣服未完全干燥之前重新穿上可能再加重湿冷。

## 59.5 低性能开销与动态LOD

只更新正在穿着的衣服，背包里的备用衣服可按容器环境和时间戳做聚合干燥；已卸下的地面衣服每个游戏分钟或房间环境变化时更新，不必每物理帧运行。低性能机上仍保留核心温湿影响，关闭复杂水滴材质不会改变玩法。

# 60. 个人清洁、血污、泥污与气味

## 60.1 污染分层

每件衣物和角色皮肤至少记录**三种独立污染**：

1. `blood`：战斗中的血液、尸体搬运与贴近喷溅。
2. `dirt`：泥地奔跑、搜查废屋、修车、拆墙、挖掘和野外作业。
3. `sweat` / `odor`：热环境和长时间高体力消耗；气味只作为轻量级近距离线索，不形成全地图持续追踪。

衣物 `wetness` 是水分，不等于脏污；烘干只降低湿度，不会洗去血和泥。反过来洗衣后污渍减少，但衣物会更湿。

## 60.2 影响范围

| 污染 | 轻度 | 中度 | 重度 |
|---|---|---|---|
| 血污 | 可见贴图污渍 | 手部/开放伤口接触时普通感染风险上升 | 触碰伤口、拆除绷带等行为更应清洁 |
| 泥污 | 外观变化 | 洗衣耗水和时间增加 | 鞋靴动作音效变化；开放伤口护理条件变差 |
| 汗液/气味 | 逐步积累 | 不适与舒适睡眠轻微影响 | 潜行时少数嗅觉丧尸的近距离搜索权重上升 |
| 潮湿 | 触发“湿”提示 | 保暖下降、重量微增 | 湿冷风险上升，需干衣和更换 |

玩家仅仅穿着脏衣服不自动损失HP；只有脏污与**皮肤破口、局部伤势、医疗操作**等事件相交时，才对 `WoundInfection` 做明确风险修正，且保留第44章对丧尸感染的独立约束。

## 60.3 洗澡和擦洗动作

交互对象：水龙头、淋浴器、浴缸、室外水桶、河流/水井边（简易清洁）、储水桶、湿毛巾和清洁用品。

| 方式 | 需要条件 | 初始耗水 | 时间（游戏时间） | 效果 |
|---|---|---:|---:|---|
| 擦手/擦脸 | 少量水或湿巾 | 0.5—1L | 10—30秒 | 清手部与脸部血污，适合处理伤口前 |
| 局部擦洗 | 水、毛巾，可有肥皂 | 1—3L | 1—3分钟 | 清指定身体区域 |
| 冷水冲洗 | 有水源和淋浴/桶 | 8—15L | 3—6分钟 | 清除多数泥污与血污，低温环境可增加冷压力 |
| 热水洗澡 | 水源、热水供应 | 10—20L | 4—8分钟 | 较好清洁，短暂改善舒适度，不能治疗疾病 |
| 野外快速清洁 | 河流/瓶装水/湿巾 | 1—5L | 1—4分钟 | 有效但效率较低，污水接触伤口可能有风险 |

以上耗水是**游戏抽象值**，可按难度缩放，不作现实水资源标准。洗澡动作会推进世界时间、消耗水与肥皂，可以被危险环境打断；完成时只结算实际清洁部分，不得因反复开关交互重复获得效果。

清洗身体前，系统提示玩家：有开放伤口时最好先使用干净水和合适护理；腐败/受污染水可能增加**普通局部伤口感染**风险。清洁不是消毒或抗感染治疗。

## 60.4 手部卫生重点

为减少操作负担，单独跟踪 `hands_dirty` 而非整套精细微生物模型。用脏手吃食物、准备生肉或给开放伤口换绷带时，根据污染等级产生小幅附加风险；洗手一次清除主要风险。玩家无需每次打开柜子都洗手。

## 60.5 环境与丧尸嗅觉交互

普通丧尸默认仍使用视觉与听觉。只有第9章配置了 `scent_detection=true` 的少数特殊丧尸，才会在距离较近、风向合理且有血污或气味线索时提高搜索概率。雨水会削弱地面残留气味，强风会偏移线索，但不允许凭一个全局嗅觉值使所有敌人凭空锁定玩家。克苏鲁默认不因血污或洗澡而修改异常关注度。

## 60.6 睡眠与SAN界限

干净床铺、干衣和合理室温可以提升**睡眠质量**，具体表现为疲劳恢复效率+3%—8%；脏湿床铺可能相反。卫生不是精神病模拟：清洁度本身不降低SAN，SAN由原有异常机制控制。

# 61. 洗衣、晾晒、烘干、供水及电力联动

## 61.1 衣物维护完整闭环

```text
衣服产生血污/泥污/湿润
 → 玩家卸下/选择清洗对象
 → 选择手洗/洗衣机
 → 校验水、清洁剂、设备状态及电力
 → 扣除资源并启动计时任务
 → 污渍逐步减少，衣物含水量上升
 → 晾晒/风干/烘干
 → 按当前含水量重新计算保暖和重量
 → 折叠/入柜/装备
```

### 手洗

- 水源：水池、浴缸、井、水桶、雨水收集器、河边；清洗污渍可使用非饮用级水，但洗伤口和身体卫生用水要求较高。
- 工具：肥皂、洗衣粉、刷子；清洁剂提高去污率，缺少时可用更多水和时间完成基本清洁。
- 时长与耗水：单件2—7游戏分钟、2—6L；重型大衣增加消耗。
- 手洗后 `wetness` 通常上升至75—100；可进行“拧干”动作使其降低约20—35点，但不等于已干燥。

### 洗衣机

- 洗衣机是第51章电网的**用电终端**，不是新种类的发电/中继节点；需要既有电网可用电、设备完好及供水容器或建筑的可用水源。
- 批量处理5—8件中小型衣物，按重量限制超载；单次消耗15—30L水、清洁剂与0.4—0.8kWh电（初始建议）；标准洗涤程序20—40游戏分钟。
- 运行中停电：暂停并记录剩余阶段，恢复电力后继续；不会重复扣整桶水/整份洗衣粉。
- 不放入不能机洗的重型护甲板、电池、武器、重要异常材料。设备UI显示禁止物品理由。

### 烘干机

- 独立**电力消费者**，每次约0.8—1.5kWh、20—40游戏分钟；仅降低湿度，不去除血污、泥土或修复耐久。
- 发热、噪音按设备配置转化为室内温度与声音事件，噪声可能吸引附近普通丧尸。
- 防止利用开关反复触发烘干完成事件；物品湿度按工作时长连续结算。

### 晾衣架/晾衣绳

- 不耗电；玩家可制作并安放，离开区块后依旧按游戏时间与天气推算。
- 室外晴朗、有风：相对快；雨天户外可能重新淋湿；室内靠近安全热源快，但封闭高湿空间较慢。
- 床、箱子中湿衣干得更慢；防水收纳袋隔绝雨水但不凭空烘干。

## 61.2 统一干燥模型

每个实例使用 `wetness 0—100`，示意：

```text
wetness_next = clamp(
    wetness_old + rain_gain + sweat_transfer + wash_gain - dry_rate × delta_game_minutes,
    0, 100
)
```

`dry_rate`由材质、室内外、风、温度、相对湿度、是否贴身穿着、是否靠近热源决定。干燥器覆盖自然干燥速率，但绝不影响污渍值。示例完全湿透衣物的自然干燥时间：晴天室外约1—3游戏小时、室内常温约3—6小时、阴冷室内更久；具体随天气与材质调整。

## 61.3 与供水系统整合

玩家据点有一个轻量级 `WaterContainerState`，统一记录：容器ID、存水L、容量、卫生水质、当前使用保留量。洗衣用水与饮用/医疗用水分配在UI中可视，避免在旱季将最后一桶饮用水洗掉。以第43章雨水收集器作为主要新增水源，洗涤可利用过滤前雨水，但不得将洗后的水自动回收到饮用库存。玩家可以在交互时选择“洗衣优先使用非饮用水”。

## 61.4 与电网和技能整合

- 电力等级决定设备安装、简单线路诊断、能耗优化；机械决定滚筒/电机修理；制作决定晾衣架、洗衣盆和修补材料配方。
- 电网负载不足按第51章优先级断电；建议洗衣机与烘干机默认低于医疗冷藏柜、关键照明及哨塔。
- **仅使用原版规划的发电端、储能和中继器网络**，洗衣机、烘干机、热水器、室内取暖器和浴室照明属于负载终端；不追加复杂电路工具或电线类别。
- 热水洗澡：燃烧加热或已有电热水器提供热水，用房屋设施UI展示可用热水，不需要真实管线网模拟。燃烧式加热装置按第51章的燃料与安全规则。

## 61.5 家居场景布置

房屋类型按第47章生成合理设备：住宅浴室有浴缸/淋浴、卫生间水池；洗衣间放洗衣机、烘干机、洗衣液架；公寓公共洗衣间有共享设备；汽车旅馆可有洗衣区；医院设清洁室；废弃农庄有水桶/晾衣绳。高端设备只在符合房屋用途的地点出现，不随机塞入每个厨房。

# 62. 感冒、环境疾病与诊疗规则

## 62.1 环境疾病原则

丧尸感染按第44章结算。环境疾病统一归 `EnvironmentalIllnessSystem`，每种疾病保存潜伏、强度、症状、治疗、康复状态。**游戏中的“受凉感冒”是生存玩法抽象**：现实感冒通常与病毒感染相关，寒冷或湿衣并不会凭空创造病毒；游戏将长时间湿冷和疲劳作为**提高上呼吸道感染易感性/触发疾病事件的因素**，而不是现实医学论断。

建议第一批纳入4种独立现象：

| 类型 | 主要来源 | 核心反馈 | 处理方向 |
|---|---|---|---|
| 普通感冒 `common_cold` | 长期湿冷、疲劳、高风险接触事件 | 咳嗽、喷嚏、体力恢复减慢 | 保暖、干衣、休息、对症药物 |
| 食物/饮水疾病 `foodborne_illness` | 变质食物、未处理污染水 | 恶心、口渴增加、疲劳 | 补水、休息、适当药物；与食物系统联动 |
| 尸体污染不适 `corpse_exposure` | 长时间滞留腐败尸堆、污染室内空气 | 恶心、疲劳、能见/气味提示 | 离开、通风、清理尸体、口罩减免 |
| 中暑/失温 `thermal_emergency` | 长时间极端冷热压力 | 行动效率下降、严重时环境伤害 | 避暑/保暖、恢复正常体温 |

开放伤口的局部感染由第4章管理，丧尸感染由第44章管理；它们可以共同增加身体虚弱，却不能相互替代或“治疗错病”。

## 62.2 感冒触发：累积暴露而不是淋一阵雨立即生病

隐藏 `cold_exposure_load 0—100`，根据以下事件增加：

- 寒冷状态且湿衣高湿度持续户外活动；
- 睡觉地点低温、衣物潮湿，且休息条件差；
- 长时间疲劳、饥渴或其他疾病使恢复效率下降；
- 区域的疾病事件/接触源作为可选触发条件（不需要复杂NPC传染链）。

在温暖、干燥、休息充分时降低暴露负荷。首次达到风险门槛后启动**一次带随机种子、冷却和抵抗力修正的疾病风险判定**，而不是每帧掷骰。推荐：湿冷持续90—180游戏分钟后才有明显患病风险；只湿15分钟不会立即出现“严重感冒”。该阈值为游戏平衡，不对应真实病程。

`DiseaseRisk = ExposureFactor × FatigueFactor × NutritionFactor × ProtectionFactor`，结果经限制区间与阶段冷却后用于抽取；必须记录 `illness_event_id`，读档和世界切换不得重复判定。

## 62.3 感冒过程（独立于七项主状态）

| `cold_severity` | 阶段 | 反馈 | 初始惩罚 |
|---:|---|---|---|
| 0 | 未患病 | 无症状 | 无 |
| 1—24 | 潜伏/轻微 | 偶尔鼻塞、轻微不适 | 体力恢复-2% |
| 25—49 | 轻度感冒 | 偶尔喷嚏 | 体力恢复-5%，喷嚏小范围声音事件 |
| 50—74 | 中度感冒 | 间歇咳嗽/喷嚏、易疲劳 | 体力恢复-10%，疲劳增长+8% |
| 75—100 | 重度感冒 | 较明显咳嗽、虚弱、睡眠不安 | 体力恢复-15%，疲劳增长+12% |

在病情缓和、睡眠和合理护理下逐渐恢复；不设置“感冒一定致死”。病情严重且长时间忽视时可触发少量短时并发症任务/高疲劳，而非跳到第44章 `ZombieInfection`。对症药物缓解咳嗽和不适但不必立即清零疾病值；抗生素不作为普通病毒性感冒的默认治疗道具。为游戏平衡设计的“综合感冒药”属于虚构用品，不给现实用药指导。

## 62.4 喷嚏、咳嗽与敌人的声音感知

- 咳嗽/喷嚏调用第8章 `SoundEventSystem`，设置声强、发生位置、遮挡、雨声掩盖和室内反射；相较枪声距离很短。
- 玩家在紧张潜行时可使用纸巾、口罩或短暂“捂嘴”动作**降低声音幅度**；不是长时间无限屏息。
- 连续咳嗽应有最小间隔与概率上限，不能一场感冒每秒触发一次。
- 丧尸仍按视听状态机调查声音；没有普通听觉的克苏鲁不因咳嗽额外建立仇恨。
- 口罩减弱症状噪声及污染源暴露，但不能替代防弹、抗咬护甲。

## 62.5 治疗行为与医疗等级

| 行为/物品 | 使用门槛 | 效果 | 制作/优化关联 |
|---|---|---|---|
| 休息、睡觉、换干衣 | 无 | 使环境暴露下降，帮助自然恢复 | 生存与床铺质量 |
| 温饮、汤类、干净水 | 无 | 口渴、饥饿与舒适度改善 | 原有饮食系统 |
| 纸巾、围巾、基础口罩 | 无 | 降低症状声音或污染吸入 | 制作5级可批量制作简单用品 |
| 一般对症药物（虚构） | 无或阅读说明后使用 | 暂时抑制咳嗽和不适，不直接治愈 | 医疗5级可制作简易护理包 |
| 医疗观察/基础诊断 | 医疗5—10级 | UI显示疾病类别、预计趋势，提高治疗效率 | 医疗技能按第5章逐级生效 |
| 高级诊疗与护理用品 | 医疗15—20级 | 改善严重疾病的康复条件 | 医院设备/研究材料 |
| NPC医疗服务 | 任务/费用 | 提供必要诊断与护理，避免单职业锁定 | 既有NPC医疗职业 |

**丧尸感染药物仍按第44章及第5章对应等级解锁。**以上是与逐级医疗技能配套的环境护理应用。冷/热、感冒、局部伤口感染和丧尸感染的药品应显示适应目标，避免玩家误以为感冒药可以治疗丧尸感染。

## 62.6 其他疾病的有限实现

**食物/饮水不适：** 容器水质与食品变质标记触发 `foodborne_illness`，以口渴增长、短时疲劳和进食效率降低表现，提示玩家净水与烹饪的重要性；持续严重症状可能造成缓慢HP损失，但不能一口变质食物立即致死。**尸体污染不适：** 使用尸体密度×暴露时长×通风系数计算风险；离开污染区域后逐步降低，防护口罩、手套及清理可减轻风险。**失温/中暑：** 只复用第59章 `thermal_stress`，不要再创建一条独立重复的温度伤害条。**衣物霉味与皮肤刺激：** 仅作为高级可选状态，长时间潮湿衣物增加气味/轻度不适，不追加数种必须每小时治疗的新病。

# 63. 衣物破损、补丁与护甲维护

## 63.1 局部破损

受击部位将使覆盖它的衣物/护甲局部耐久下降。建议使用“部位耐久百分比+破洞标签”而不是在每张低模网格上做实时布料破裂模拟。一个左臂破洞会降低左臂抓咬防护、防雨和保暖；右臂仍按照未破损数据计算。装备耐久到零时标记报废，保留可拆回收材料。自动维修不应在存档加载时发生。

## 63.2 修补类型

| 修补方式 | 材料 | 工具/工作台 | 效果 |
|---|---|---|---|
| 临时缝合 | 针、线、布片 | 手工 | 恢复部分基础耐久与保暖，不保证抗咬完全恢复 |
| 同材质补丁 | 牛仔布、皮革片、合成布 | 裁缝工具或工作台 | 恢复局部防护，并产生略可见补丁 |
| 强化衬垫 | 厚布、皮革、轻量护板 | 高级制作台 | 增加抓/咬防护，同时提高重量与闷热 |
| 防水修补 | 防水布、胶带、密封材料 | 手工/工作台 | 恢复雨衣局部防水能力 |
| 护甲板替换 | 专用护板与固定件 | 防护装备维护台 | 主要恢复弹道/重型防护，与普通缝补分开 |

## 63.3 与十技能的关系

- **制作5级**：基础针线、布片修补、简易晾衣绳；**10级**：皮革、牛仔补丁；**15级**：防水修补与基础衬垫；**20级**：复合衬垫及护甲载体加工；**25级**：高级定制防护与复杂维护。此为追加解锁，不删除原有建造配方。
- **生存**：制作简易露营干燥架、野外衣物护理、识别安全水源；不决定护甲材料加工。
- **医疗**：清洁伤口和换绷带，不负责衣物强度属性。
- **机械/电力**：洗衣烘干设备修理及接线，修补服装仍为制作技能。

## 63.4 资源循环与防刷级

拆解坏衣可得到布条/线/皮革残片；修补后可以继续使用，但每次修补有**可恢复耐久上限**和材料消耗，防止无限刷品质。经验按“首次修复有效损失、材料消耗、实际获得耐久”发放，反复脱穿、洗干净衣物或洗已干衣服不能刷制作/电力经验。

## 63.5 战斗与外观

以可复用贴图遮罩/局部材质叠层表现血污、泥污、破洞和补丁，不要求给每件衣服制作数十套glb。防护属性以数据为准；特效不改变碰撞体与七部位判定。血污和湿度的视觉更新分级，远处角色仅用低精度状态标记。

| 简易隔离休息床 | 患病期间安全休养 | 无 | 床位、保暖条件 | 医疗室、卧室 |

## 64.2 室内热环境

每个被封闭屋顶与墙体包围的 `RoomVolume` 保存简化室温修正值与通风评分：墙体/窗户保温、门开闭、破窗、火炉或电热器的热量、外部气温。不是逐格CFD；若室内封闭空间太大，按照房间与门连通关系分区更新。玩家开门/砸窗可以使室温向室外靠拢。安全热源不得在玩家离线或场景卸载时无限免费产热；燃料消耗遵循世界时间戳。

## 64.3 用电优先级示例

1. 医疗冷藏、核心安全照明；
2. 关键防御哨塔；
3. 取暖器（寒潮可提高优先级）；
4. 热水器；
5. 洗衣机、烘干机、装饰照明。

优先级可在配电UI调整，但不改变第51章“发电机/燃烧式发电/太阳能/电池/中继器与线路”的网络结构。若电量不足，洗衣机暂停但不删除衣物或洗涤进度；哨塔控制仍受原有电力与弹药双门槛。

## 64.4 防御与生活空间的取舍

玩家把房间作为洗衣、睡眠、医疗区，必须考虑噪声、出入路线、设备电力和窗户加固。洗衣机等机器声可能形成声音事件；若被丧尸群发现，不需要设置“洗衣必然引发尸潮”的固定脚本。把住宅改造成据点时需保持浴室、卧室、储物间可通行，不在门口任意摆家具导致NPC守卫卡住。

## 64.5 主世界与颠倒世界同步

- 衣物实例、箱子里的服装、洗衣机内库存与运行程序、晾衣架上的衣物、房屋墙体与热源/电力设施仍以**同一共享实体ID**存在，不能两边各洗一次或各取一件。
- 玩家正在穿着的衣物和所有个人卫生/感冒数据属于唯一 `PlayerState`，切换世界不重置。
- NPC守卫仍只在主世界正常活动；在颠倒世界不生成对应NPC副本。
- 环境气候计算读取基础天气和当前世界层异常覆盖；两侧若局部温度不同，可改变**同一件衣物**的后续湿润/干燥速度，但世界时间只前进一次，不能对同一个离屏实体重复结算两个世界。
- 洗衣机、烘干机和热水器通过共享电网供能；场景切换只更改表现，不复制耗电量。
- 裂隙触手拖拽期间，根据动画/控制状态决定是否允许穿脱衣物交互，避免动作冲突；所有已经成立的清洁交易保持存档一致。

# 65. UI设计、物资生态与提示

## 65.1 HUD：圆形主状态与临时病症环

常驻HUD采用六个圆环：HP、饥饿、口渴、疲劳、SAN、丧尸感染。全部**图标放在圆心**，外圈用各自颜色表示0—100进度，圆环和图标支持低饱和配色、危险阈值与色盲辅助纹理。体力属于第七项核心状态，单独以圆环跟随角色右侧投影位置，在体力消耗时显示、停耗1秒后开始约0.25秒淡出，低于20%时保留提示。

临时状态显示寒冷/过热、衣物湿透、感冒/发烧、严重血污、出血、骨折、破损。寒冷与过热**共用体温压力环**，圆心雪花/火焰按实际冷热状态切换；疾病圆环用于症状严重度，不视为第二条HP。可合并“湿透+寒冷”为一条提示，避免重复预警。丧尸感染与普通伤口感染、感冒必须分开。

主状态环位于左下角2×3排列，临时圆环可在其上方按优先级显示最多三个；底部中央固定六分类快捷栏，屏幕上方仅在选具体物品时弹出横向列表。完整布局、数值及显示阈值按第102章实施。

## 65.2 角色装备面板

建议支持3个子页面：

1. **服装**：层级、槽位、外观预览、重量、湿度、污渍、耐久、保暖、防水、透气。
2. **身体防护**：沿用七部位人体轮廓，选部位看抓伤/咬伤/弹道防护，查看哪个衣服有破洞。
3. **健康与环境**：当前冷热等级、衣物湿度、感冒症状、皮肤血污、当前药物及治疗趋势。

装备比较只列**相对于当前穿着变化**的关键值，例如“防水+25、保暖-10、移动惩罚+4%”，避免几十个小数影响决策。

## 65.3 洗衣与洗澡UI

交互界面展示：可清洁对象、已有水量、清洁剂、预计时间、用电/供水、衣服清洗后湿度和是否有晾晒位置。对耗费昂贵洁净水的洗涤动作给出简单确认。洗澡开始前显示“冷水/热水”，无法供热时回退为冷水并改变寒冷风险提示。

| 事件/接口 | 触发方 | 处理者 | 保证 |
|---|---|---|---|

## 66.4 冷热压力伪代码

```gdscript
func step_environment(game_minutes: float, local: Dictionary) -> void:
    var total_insulation := ClothingSystem.get_effective_insulation()
    var total_breathability := ClothingSystem.get_effective_breathability()
    var activity_heat := PlayerMovement.get_activity_heat()
    var cold_pressure: float = maxf(0.0, local.get("cold_index", 0.0) - total_insulation * 50.0)
    var heat_pressure: float = maxf(0.0, local.get("heat_index", 0.0) + activity_heat - total_breathability * 15.0)
    var wet_cooling: float = PlayerEnvironment.get_aggregate_wetness() * 0.03
    PlayerEnvironment.thermal_stress = clampf(
        PlayerEnvironment.thermal_stress + (heat_pressure - cold_pressure - wet_cooling) * game_minutes * 0.05,
        -100.0,
        100.0
    )
```

这仅展示**单一写入者和顺序**；正式项目应通过 `WeatherProfile` 配置冷/热指数，平衡全零天气和恢复向舒适值的衰减，不能原样把上述数字当成真实温度模型。

## 66.5 清洗事务伪代码

```text
commit_hygiene_action(action_id, actor_id, resource_ids, targets):
    if action_id already completed: return cached_result
    validate distance/room/water/soap/unlocked-action/wearable-items
    reserve water + consumables
    start activity and save remaining duration
    on valid completion: consume reserved resources once
                         update skin/clothing pollution or wetness once
                         mark transaction completed; notify UI
    on interruption: release unused reserved resources;
                     persist completed partial progress; never duplicate items
```

洗衣机/烘干机将同一事务拆成清洁、漂洗、脱水、干燥等阶段，换世界/掉电/离开区块以后继续依据唯一任务状态结算。不能创建第二套电力或供水库存。

## 66.6 存档字段与兼容

`save_schema_version = 4.1`，升级时：

1. 玩家始终使用七项核心状态、十技能、`ZombieInfection`、`WoundInfection`、武器和电网。
2. 对已有衣物实例补充缺失的 `wetness=0`、`dirt=0`、`blood=0`、`condition=原耐久或满耐久`；局部破洞为空。
3. 对旧角色的单一 `wetness` 转成 `skin_wetness` 和**已穿着外层**的初始湿度，避免旧档读入后凭空全身干燥；随后旧字段改为只读派生值。
4. 初始化 `thermal_stress`沿用第43章原值；新增疾病默认健康，`cold_exposure_load=0`。
5. 旧地图已有洗衣机、浴缸等装饰物以**固定旧实体ID**赋予新交互组件，不能重生成物品库存。
6. 洗衣任务、干燥任务、感冒症状事件和供水事务均以唯一ID写存档；新版本重复读档不增加副本或双倍扣电。
7. 迁移只执行一次并写版本日志；回退旧版本需备份存档，不保证旧代码理解新增状态。

# 67. 系统联动、平衡护栏与设计样例

## 67.1 七项状态的最终修正层

`PlayerStats`统一整合第3章的状态、第6章体型、第7章负重、第44章丧尸感染、第59章冷热与第62章环境疾病。建议优先级：基础属性→基础技能与体型→装备重量/护甲→明确的身体伤势→感染/疾病→环境冷热→最终软下限/上限。UI能展示主要来源。

**可控负面效果例子：**体力恢复基础8点/游戏分钟；轻微感冒×0.95、寒冷×0.92、重装×0.90 → 约6.29点/分钟。不要为同一“穿重衣导致过热”的来源再次把相同的行动惩罚计算两遍。沿用第52章的行动速度一般恢复性debuff下界35%。

## 67.2 示例情境一：雷雨中的居民区搜刮

玩家穿T恤、牛仔裤和防弹背心外出，突发大雨：外层裤子逐渐湿透，背心下方因奔跑也积汗。丧尸在雨声中更难捕捉部分脚步，但玩家的保暖开始变差。玩家进入屋内，找到一件雨衣、一桶清洁水和毛巾，并更换装备。搜刮时与一只丧尸发生近战，左臂外套被抓破且局部伤口受伤。玩家先脱离战斗，止血、正确清理伤口，然后再考虑洗手、清理衣物。雨衣可以改善后续挡雨，但不能修复已经形成的伤势或消除第44章感染。

## 67.3 示例情境二：寒潮夜的据点维护

夜间寒潮到来，太阳能发电停止，锂电池剩余电量有限。玩家为重要照明和哨塔保留电力，用原有燃烧炉给室内提供热量，把湿大衣挂上晾衣架。洗衣机因优先级低而暂停；供电恢复后继续。角色在干燥房间睡觉，`thermal_stress`回到舒适区，潜在感冒暴露值下降。NPC守卫不因供电中断凭空消失，也不会自动免费给玩家清洗全部衣物。

## 67.4 示例情境三：感冒潜行与克苏鲁遭遇

玩家连续湿冷探索后在次日出现轻度感冒，偶尔打喷嚏。夜晚进入医院时，喷嚏在走廊向附近普通丧尸发出声音；玩家使用纸巾和掩体减少暴露，仍需要注意敌人视觉。随后进入异常区域，面对克苏鲁狩猎者时，原有特殊感知、仇恨累积、最后位置追踪与光源机制保持不变：感冒不会增加异常关注度，也不会把普通听觉规则强加给克苏鲁。玩家穿越裂隙后感冒症状、干湿衣物和药物效果继续存在。

## 67.5 示例情境四：穿甲与散热取舍

玩家准备攻击危险工业区，可选重型防护作业服（较高抓咬防护、闷热、沉重）或防水冲锋衣配轻型胸甲（防雨与机动较好、防御中等）。夏季连续近战更适合后者；冬季低温遇特殊丧尸可能更需要内搭保暖衣或专用护甲。装备选择由场景和风险决定，而不是单纯追求防护数值最大值。

| 服装保暖、防水、透气 | 0—100，材质差异见第58章 | 装备选择有取舍 |
| 单件湿度 | 0—100 | 真实反映穿脱、天气、洗涤差异 |

## 68.4 验收工作原则

先验证规则，后制作服装资产数量；先实现装备/护甲影响，再追加污渍材质与布料细节；先实现一种感冒，再扩展食物与尸体污染疾病。场景完成判断必须包括：能在游戏里操作、正确显示、消耗一次资源、可存档、跨区不复制、双世界不重复计时、敌人感知符合原有规则。

# 69. 系统一致性、功能优先级与实施边界

## 69.1 系统数据的一致性要求

1. 角色湿润数据以皮肤湿度与单件衣物湿度为真实来源，角色级 `wetness` 为只读聚合值。
2. 七部位伤害与局部衣物覆盖防护分别计算；丧尸感染、伤口感染和环境疾病不得共享同一变量。
3. 服装、护甲、武器、车辆及其零件均使用独立物品实例ID；装卸与修补不复制物品。
4. 洗衣机、热水设备、车库充电器、哨塔与照明共用第51章电网结算，不重复发电或耗电。
5. 世界时间、天气、感染与疾病均引用统一的时间管理器；睡眠、存档、跨区和切换世界只结算一次。
6. 共享世界实体使用唯一持久状态。车辆可驾驶物理实例仅处于一个活跃世界层；另一世界的视觉映像不参与交互。
7. NPC身份唯一；随载具跨世界的乘员可在目标层临时活动，但不得在原层产生第二个NPC。
8. 裂隙进入/返回、车辆货厢交易和任务奖励需要唯一事务ID与失败恢复流程。

## 69.2 工程集成检查

- 已有七项状态的HUD、局部伤势计算与冷热/疾病修正是否只在`PlayerStats`聚合一次。
- 受击伤害是否把“护甲格挡/未穿透/感染暴露”三种结果单独传递。
- `PowerGridManager`是否允许消费者在断电后暂停并恢复，不需另建机器电网。
- 门窗/屋顶是否能向 `RoomClimateSystem`提供正确的封闭遮蔽信息。
- 所有洗衣、医疗和穿脱行为是否使用既有物品唯一ID而不是复制出新的衣物实例。
- 世界时间是否统一，尤其是跨世界、睡觉快进、区块卸载与读档阶段。

## 69.3 阶段交付边界

基础内容实现“衣物分层、5—10种代表性服装、基本抓咬防护、温湿和出汗、洗手、手洗、晾衣、感冒和基础UI”。拓展内容包括“完整的家用洗衣机/烘干机/热水设备、更多服装材质、局部防护补丁、冬季装备、不同区域疾病与NPC任务”。长期内容按实际玩法价值扩展“更多衣物外观、专用防护套装、长期气味、复杂温室/室内空气和更细致的医疗状态”。

所有开发阶段都必须保持**角色七状态、十技能、两世界共享物品、电网单实例**四条基础约束。

## 衣物与疾病机制参考资料

- 《僵尸毁灭工程》官方游戏API中的`Clothing`字段包括`insulation`、`waterResistance`、`windresistance`、`wetness`、`bloodLevel`、`dirtyness`和`patches`等：<https://www.projectzomboid.com/modding/zombie/inventory/types/Clothing.html>。本项目参考这些系统分类，不照搬其内部算法。
- 参考独立资料的游戏机制说明：<https://pz-guide.com/en/status/hasacold/>（感冒症状分级）；<https://pzfans.com/how-to-dry-clothes-in-project-zomboid/>（血污、污渍和湿度的独立处理）。版本差异可能存在，数值由本项目自行设计。
- **现实医学区分：** 感冒通常涉及呼吸道病毒，而不是单纯由寒冷直接产生；本方案的湿冷暴露是一种游戏内疾病风险抽象。感冒症状药、抗感染剂和特殊血清都只作为游戏道具规则，不构成医疗建议。
