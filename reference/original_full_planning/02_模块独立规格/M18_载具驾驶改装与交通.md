# 70. 载具系统：定位、设计边界与核心循环

## 70.1 设计定位

载具是开放世界探索、撤离、物资运输、野外临时庇护和据点后勤的组成部分。参考《僵尸毁灭工程》中“寻找车钥匙、检查车辆状态、消耗燃油与电池、零件损坏和维修、驾驶噪声吸引尸群、后备箱运货、拖车、车内休息”的生存体验。这里的车型、状态参数、技能门槛、物理模型和裂隙行为为本项目独立设计，不要求与参考游戏的具体数值一致。

核心循环为：发现车辆→确认安全并检查状态→寻找钥匙/合法启动车辆→加油或修理→规划道路和天气→装载物资→驾驶、避开尸群和异常区域→返回据点停车卸货→维护零件、补给燃油。高污染地带还存在车辆被裂隙捕获、玩家连车进入颠倒世界的风险。

载具不是无代价的快速旅行：驾驶快、装货多，却依赖道路、燃料、零件状态、噪声和载重；在窄巷、受阻道路和裂隙前，徒步或轻型载具可能更安全。

## 70.2 运行规则

- 所有载具拥有稳定不重复的 `vehicle_id`；存放燃油、损坏、载具库存、所在世界层、坐标、座位占用及牵引关系。
- 载具是地图可持续对象，不因玩家驶离、离开区块、睡眠、进入建筑或切换世界而重置。
- 仅具有驾驶资格和座位占用权的角色可发起驾驶输入；车钥匙、车锁、点火状态分别记录。
- 引擎声音、喇叭、撞击玻璃和车载报警器加入统一 `NoiseEventBus`；前照灯加入统一 `LightStimulus`，但克苏鲁仍依第10、27章的视觉/异常/光源感知，不套用普通丧尸听觉。
- 车内玩家的七项主状态、七部位伤势、疾病、药效和SAN按世界时间连续结算；车辆只能部分抵御环境，不能提供无条件安全。
- 主世界与颠倒世界共用车辆的**持久数据**；车辆某一时刻只能有一个**可驾驶的实际物理实例**，其活跃世界层由 `active_world_layer` 决定。另一层可生成无碰撞、不可交互的视觉映像以维持空间对应感。

## 70.3 车辆生命周期

`WORLD_SPAWNED → PARKED → INSPECTED → LOCKED/UNLOCKED → IGNITION_ATTEMPT → ENGINE_RUNNING → DRIVING → PARKED/STALL/INCIDENT → REPAIR/TOW → PARKED`。

裂隙触发时临时进入 `RIFT_TARGETED → RIFT_LATCHED → RIFT_DRAGGING → RIFT_TRANSITION → INVERTED_WORLD`。失败则回到正常驾驶、抛锚或受损状态。状态机必须允许多种自然事件中断，例如引擎熄火、玩家受击、车辆碰撞、弹射、座椅乘员下车与区域流式加载。

## 71.2 静态配置与动态实例

`VehicleDefinition` 保存车型、外形尺寸、轮距、轴距、座位锚点、碰撞形状、引擎性能曲线、轮胎/零件兼容类别、油箱容量、容积/重量上限、前后灯点、保险杠、车门和货厢相对位置。

`VehicleInstance` 保存唯一ID、世界坐标、速度、朝向、实际所在世界层、发动机开关、档位、油量、油耗计、零件实例、乘员与车内物品、当前物理状态、牵引关系及异常事件ID。同款车型的多台汽车不能共享电量、钥匙或后备箱。

## 71.3 地图分布和环境叙事

住宅车道、超市停车场、医院急救入口、警察局车库、加油站、维修厂、山区道路、废弃事故点等使用不同车型池与损坏分布；已停在民宅门口的车可能在相应房屋抽屉中找到匹配钥匙，事故路段更可能有破胎和车损，维修厂附近更容易找到千斤顶、扳手与可拆零件。可搜刮物资按“车辆原用途”决定，避免所有后备箱都是相同随机物品。

载具路障包括侧翻车辆、失去车轮的空壳、长时间停放的车辆与堵住桥头的货车。道路和桥梁宽度必须按车宽、转弯半径、拖车长度及NPC跟车导航校验；普通乡道、城市街道、地下停车场与建筑车库的出入口使用明确碰撞和高度限制。

## 71.4 场景生成和物品防重复

静态车辆由 `spawn_point_id + world_seed` 生成初始车型、损坏、燃料、车钥匙关系和车内物品一次，并写入 `SharedWorldState`。其后变化只能由持久化实例更新。已搜刮的后备箱、已移走的车与拆下的轮胎不得在再次进入区块后刷回；跨世界映像不运行战利品生成。

# 72. 发现车辆、上下车、座位与点火

## 72.1 车外检查

玩家接近车辆可执行“观察外观、检查车门、查看轮胎、查看后备箱、打开引擎盖、检查油箱”等交互。低机械技能只给粗略信息（有无轮胎、玻璃完整、明显漏油）；等级提升后显示零件耐久、故障原因、推荐维修材料。锁着的门和后备箱需车钥匙或相应开锁/破窗手段；强行破窗产生声音、玻璃伤害风险与永久车损。

## 72.2 车钥匙与启动权限

每台车辆对应一组 `key_code`，可在点火处、座位、储物格、附近建筑或周边原车主身上出现；钥匙物品可以有多个实例，但都仅匹配相同车辆的 `key_code`。玩家坐到驾驶席才可执行正常点火。机械损坏、无油、无电或点火系统损坏都可能使“有钥匙”仍无法启动；UI必须提示对应故障。

保留紧急线路接通（热接）作为无钥匙解决路径：使用工具与技能检查，建议机械等级≥5且电力等级≥5才可开始尝试；技能不足可通过找到车辆说明/专用套件降低门槛。热接有持续操作时间、失败损坏点火器和触发报警器的风险，成功后生成该车唯一的 `ignition_override` 状态。上述门槛是本项目方案，不是《僵毁》的原始要求。

## 72.3 上车、选座与启动交互

1. 玩家到达目标车门的可达交互点，执行上车动作。房间的自动过门机制继续独立运行；上车使用车辆上下文交互，避免跑过汽车时误进入。
2. 检查车门是否存在、可开启、被其他物体堵塞，目标座位是否空闲；开门、坐下、关门动作使用可打断动画与移动约束。
3. 玩家进入驾驶席后镜头柔和过渡到跟车视角（相机可自由旋转、拉远、观察后方），仪表显示车速、油量、电瓶、发动机、温度与故障标记。
4. 先点火（钥匙/热接许可、燃油、电量和发动机满足条件），进入短暂启动动画，再切到运行状态；**按前进键不能无条件自动启动任意坏车**。
5. 启动后油耗与怠速噪声实时生效。挂挡、松开驻车制动，开始驾驶；允许基础自动挡简化，保留前进/空挡/倒挡/驻车状态。
6. 停车且车速低于阈值时才能正常离车；紧急跳车单独判定坠地伤害与惯性。驾驶座、乘客座允许车内换座，但须检查座位占用和动作空间。

UI 提供“点火、车灯、喇叭、车门锁、取出钥匙、换座、收音机、雨刷、暖风/空调、查看车辆、后备箱、下车”等车辆上下文操作。快捷键可配置；不得与默认武器/玩家交互输入硬冲突。

## 72.4 NPC上车与下车

NPC从世界导航到各自车门，并等待座位预约成功再执行上车动画；需要避免所有NPC挤在驾驶门口或与玩家同时传送上车。上车期间记录 `reserved_seat_id`，在取消动作、NPC受击或车辆突然起步时释放预约。上车成功后NPC成为当前车辆的乘员锚点，由车辆坐标统一驱动。下车选择道路侧/车门周围安全点，避开玩家、丧尸、建筑与车辆轮廓，失败则提示“出口被堵住”并允许换另一侧座位。

NPC只提供有限护卫、治疗/维修提示与物资运输协助，不自动驾驶全图、不自动清理地图；载具属于单人游戏的后勤扩展。

# 73. 驾驶手感、地形、燃油和运动模型

## 73.1 操作和动力学

采用适合Godot 4.x的**轻量可控物理驾驶**而非精密赛车模拟。标准车辆使用 `VehicleBody3D` / `VehicleWheel3D` 作为可行的原型选择，或自建基于 `RigidBody3D` 的简化轮胎抓地模型；二者必须在坡道、满载、拖车和碰撞场景中实测后择一。驾驶油门、制动、方向、倒挡与手刹是持续控制输入；转向角随速度提高而减小，防止高速满角转向异常翻车。

核心动力学参数：整备质量、载荷质量、驱动扭矩曲线、转向角、制动强度、轮胎抓地、地面摩擦、风阻、坡度、悬挂阻尼。**载荷体重直接参与车体总质量**，不能仅改变HUD的“载重”标签。考虑新手驾驶辅助（低速转向辅助、翻车容错、自动换挡），不强制玩家手动踩离合器。

## 73.2 地面系数与天气

| 地面/天气 | 抓地相对倍率（建议） | 实际影响 |
|---|---:|---|
| 干燥柏油 | 1.00 | 普通转向、制动 |
| 湿柏油 | 0.80—0.90 | 制动距离增加、急弯易打滑 |
| 碎石路 | 0.65—0.80 | 车体震动、轮胎磨耗增加 |
| 泥地 | 0.45—0.65 | 行驶阻力变大、低底盘易陷车 |
| 雪地 | 0.40—0.65 | 起步打滑、低速转向不稳定 |
| 冰面 | 0.20—0.40 | 严重制动不足，高速难控制 |

上述倍率以基础轮胎及轮胎状态为基准，越野胎在泥地/碎石更有效，冬季胎在雪面更有效，但它们不能同时在全部路面取得最高性能。暴雨可在低洼地形成临时积水，严重涉水导致失速/发动机故障；只在地图明确定义的可驶入水深范围内计算，不凭任意雨滴随机熄火。

## 73.3 油耗和行驶里程

用游戏化真实量纲记录油箱容量（L）和燃油量（L）；油耗根据车型基础值、转速负荷、速度、坡度、载货、拖车和空调/怠速调整。建议 `fuel_used_L = idle_L_per_hour × dt_h + drive_L_per_km × distance_km × load_mult × slope_mult × damage_mult`，但怠速与行驶部分不得在同一时段重复统计同一基础消耗。无油时由运行转为熄火，不删除车辆速度惯性。

油箱破损造成燃油流失；柴油与汽油的载具类型不同，燃料库存与第51章据点燃油设备使用兼容的物品定义，但不能误将水/污染液体当作发动机燃料。车辆停放仍可手动加油、倒油或补充备用油桶；燃油物品发生交易时必须原子扣除来源容积。

## 73.4 启动、熄火和电瓶

发动机运行可按配置给汽车启动电瓶充电；车灯、报警器、收音机、雨刷、风扇、空调在发动机停止时耗电。电瓶保存**健康耐久（%）**与**当前电量（Wh）**，两者不同；有电但健康很差可能难启动。短途重复点火消耗电瓶；熄火后忘关车灯会导致亏电。发电机组、汽车充电器与据点电网可在玩家连接合法设备时为电瓶充电，但电池必须是汽车规格实例，不能把据点大型锂电池直接无代价插到普通轿车启动位。

# 74. 车辆零件、损伤诊断、维修与拆解

## 74.1 零件与条件状态

| 部件 | 独立状态 | 失效表现 | 维修方式 |
|---|---|---|---|
| 发动机/点火器 | 耐久、故障、启动概率 | 难启动、熄火、动力下降 | 机械维修、部件替换 |
| 电瓶/发电机 | 健康、充电量、发电能力 | 启动困难、灯光/雨刷失效 | 电瓶更换、充电、电力维修 |
| 油箱/油路 | 油量、容积、泄漏 | 漏油、行程缩短 | 修补/更换、加油 |
| 四组轮胎 | 健康、胎压、适用路面 | 抓地变差、爆胎、跑偏 | 充气、补胎、更换 |
| 刹车 | 前后制动效率、磨损 | 停车距离增长、偏刹 | 调整、更换 |
| 悬挂与转向 | 耐久、转向精度 | 颠簸失控、转弯困难 | 零件更换 |
| 车头护板/保险杠 | 分区耐久、材质 | 冲撞伤害直接传到车体 | 焊补/替换 |
| 车身/车门 | 耐久、门锁/开启 | 碰撞后无法打开、进水 | 维修、钣金、换门 |
| 车窗/风挡 | 破损、透明/污渍 | 视野、玻璃伤害、雨水进入 | 更换玻璃、清洁 |
| 车灯/雨刷/暖风 | 耐久、通电、开关 | 夜视、恶劣天气操作受限 | 电力/机械维修 |
| 后备箱/货箱 | 盖板耐久、锁、库存容量 | 货物暴露、容量下降 | 修理门板、货箱加固 |
| 座椅/安全带 | 耐久、能否使用 | 撞击时乘员风险提高 | 修补/更换 |
| 排气/消音器 | 噪声倍率、耐久 | 噪声升高、潜行难度变大 | 更换部件 |

完整车辆具备 `0—100` 的零件耐久和 `broken` 故障标记；**耐久0不必然将对应实例销毁**，允许维修、拆下或作为废料利用。不能通过卸装高耐久部件把车体的整体损伤自动清零。车体正/侧/后碰撞区分伤害流向相应部件。

## 74.2 维修流程与技能

1. 将车停在可操作位置，熄火、驻车；进入维修面板，点击部位显示故障原因和操作条件。
2. 根据车辆类型检查兼容零件ID、工具、耗材和技能等级。
3. 普通易损件如车灯/电瓶可以用较低机械或电力等级更换；发动机、制动和复杂线路要求更高技能与维修台。
4. 修理、拆卸或安装要消耗游戏时间，在外部危险环境可被打断；先检查资源和背包容量，成功时再提交一次性事务。
5. 失败可消耗少量耗材、降低零件状态或产生噪声，但不能让玩家无限无成本刷技能。
6. 机械、制作和电力三项技能分工：机械主导动力/底盘、制作主导焊接与外部加固、电力主导启动/电路与用电设备。

零件标签 `family=standard/heavy/sport` 与 `compatible_models` 限制通用性，给修车厂和报废车辆拆件实际价值。常见小车零件可多车型兼容，特殊警车/救护车的附属系统需要对应组件。

## 74.3 汽车与零件报废

不再可安全驾驶的汽车仍可作为移动掩体、路障、报废材料来源或运输回收目标。拆除后备箱内物品先通过标准库存转移，拆车不会神秘产生与后备箱内容无关的复制资源。使用千斤顶等工具时地形和倾角影响操作合法性。重型车厢、发动机等大型部件可以占用货厢物理槽位，不能随意放入玩家普通口袋。

# 75. 载具库存、装载、乘员与车内空间

## 75.1 容器分区

驾驶席储物格、前排脚部、手套箱、后排座位、后备箱、皮卡货斗、车顶架、拖车库存分别有独立 `container_id` 和容积/重量/物品类型限制。车辆实际库存沿用第7章**网格格子＋重量**体系，并额外增加大件尺寸和容积阈值；物品旋转、堆叠、拆分和转移仍使用背包公共接口。

车厢与后备箱容量受车身改装、车门/盖板损坏、座椅折叠和已装设备影响。车顶架携带大件时增加重心、风阻与翻车倾向；货斗未固定的物资在剧烈碰撞中可能散落到共享世界地面实例。

## 75.2 座位和货物的取舍

座位 `occupied` 时不能当成额外免费库存；折叠/拆除后排座椅获得货舱空间，但减少可载NPC人数。每个乘员有自身体重、个人背包重量和乘坐状态，整体计入车辆载荷。车内人数超过法定座位数时禁止正常上车（不做无限叠罗汉）。未系安全带的乘员在撞击时受到更高伤害。

## 75.3 物资运输事务

物品从玩家背包→货厢必须使用一次原子库存转移：确认车厢可用且空间/重量足够，扣除来源物品实例并将同一物品实例的持有者改为目标 `container_id`。存档和世界切换后不得同时存在车内与背包两份相同 `item_instance_id`。货厢打开、战利品装卸、拖走车辆都产生适当声响和操作时间。车辆摧毁时先结算车厢损坏/爆炸对物品的影响，残存物资掉落成唯一共享实例。

## 75.4 车内生存

封闭车厢在雨雪下提供遮蔽和有限保温；窗户破损、车门未关严、空调/暖风损坏会改变效果。玩家在安全停放的车辆里可以吃喝、使用简易医疗用品、查看地图、整理小物品、短暂休息或睡眠，但舒适度低于良好床铺，周围丧尸可能围车、敲窗、堵门。驾驶中允许有限乘客动作；驾驶者使用背包/药物受分心与操作状态限制，避免“边高速驾驶边拆引擎/换衣服”。

# 76. 交通事故、尸群互动、噪声与车载照明

## 76.1 碰撞与伤害

碰撞强度结合相对速度、接触法线、车体质量、撞击部位、障碍类型和保险杠状态计算。低速擦碰主要损坏车漆/保险杠；高速正面撞击可损毁引擎、车灯、轮胎和乘员；侧翻可能使车门无法开启。车内乘员的损伤映射至第4章七部位，并由安全带、座椅和撞击方向修正；负伤角色可能有头晕、手臂受伤造成的方向控制不稳。极高速度碰撞应以可理解的动画、声音和故障状态提示，而非突然删除车辆。

## 76.2 车辆与丧尸

低速推撞丧尸可能使其失衡，但多只尸群拥堵、反复冲撞会磨损保险杠、底盘和发动机。撞击丧尸可造成引擎盖血污、玻璃碎裂和轮胎磨损；血污属于车辆外观状态，不会自动增加玩家七项中的感染。丧尸可能敲窗、抓门、打碎玻璃并尝试攻击车内角色；窗户完整且门锁正常时先攻击车辆对应零件。

车辆碰撞不能成为无风险持续割草手段：密集冲撞会减速、偏移、损坏发动机，导致车辆在尸群中心抛锚。玩家可以有策略地用喇叭把尸群引离医院，但噪声会招来更多丧尸而且可能堵死退路。

## 76.3 统一声、光事件

| 事件 | 丧尸影响 | 克苏鲁影响 |
|---|---|---|
| 发动机怠速/加速 | 按噪声强度吸引周围丧尸 | 仅视觉及特殊感知相关 |
| 喇叭/警报器 | 形成较强、持续的声音调查目标 | 不赋予普通听觉反应 |
| 碰撞/破窗/急刹 | 短时声音事件，附近丧尸调查 | 可见受击反应或特殊感知 |
| 夜间车灯/远光灯 | 改善玩家视野，也可能暴露位置 | 能直接照射具光源感知的克苏鲁则可增加仇恨 |
| 熄火/关灯/停车 | 降低持续噪声和光源威胁 | 不自动清空已有仇恨和最后位置记忆 |

开灯照亮克苏鲁后关闭灯光，克苏鲁仍使用第27章仇恨与搜索记忆，不出现一关灯即瞬间失忆。车辆经过固定型克苏鲁领域时，敌人主体不离开固定锚点，但可攻击车体和车内玩家。常规视觉型敌人需要对车窗透明度和车身遮挡做视线检测。

# 77. 载具与天气、体温、道路、视觉的联动

## 77.1 车外环境

天气状态由第43章 `WeatherManager` 提供，不单独为车辆生成第二套雨雪。湿滑度、能见度、积水、风和季节温度作用于轮胎抓地、发动机效率、车窗状态、车内舒适度与行车灯光。大雾或暴雨降低驾驶员有效视距，但不直接修改物理引擎的刹车扭矩；滑路制动危险源于轮胎抓地下降。

## 77.2 车内微气候

车厢保存 `cabin_air_temperature`、`window_fog_level`、`interior_wetness`、`heater_state`、`ac_state`、`window_open_fraction`。车厢隔绝雨水的能力由车窗、车门和顶棚完整度决定；车辆暖风/空调耗发动机燃料或电瓶电量。角色热舒适与衣服湿润仍使用第59章通用结算，只把车厢作为新的环境输入，防止一次更新两次体温/出汗。

## 77.3 驾驶可视反馈

雨刷在下雨时提高风挡有效清晰度，雨刷损坏导致视线恶化；暖风除雾、开窗换气可改善玻璃起雾，但寒冷环境开窗降低保温。夜间远光可延长道路可见距离但扩大被光感知敌人注意的条件。雪天车辆启动后需要短暂暖机表现，严寒减少老化电瓶的可用电量，不能仅因为天气切换就强制停机。

## 77.4 典型生存决策

夏天越野行驶满载皮卡会提高油耗并增加过热风险；冬季在堵塞路段长时间怠速等待需要考虑剩余油量；暴雨中车辆能避雨，但玻璃被撞坏后车内仍会被淋湿；夜间关车灯穿越异常区有利于降低光源风险，却使驾驶更危险。天气惩罚设置上限，避免低级载具在每场普通小雨中完全不可使用。

# 78. 拖车、牵引、救援、据点车库与道路后勤

## 78.1 牵引与挂接

支持可拆挂的货物拖车和故障车牵引：只有具备有效 `tow_hitch` 的主车可在低速停车时执行挂接。检查两车连接点距离、朝向、牵引重量、相对坡度和主车牵引等级；挂接成功后形成双车的单一牵引拓扑。拖车容量属于独立实例和库存，不并入主车后备箱。

行驶时拖车增加质量、制动距离、转弯半径和倒车难度；过载或剧烈摇摆有断开/侧翻风险。进出较窄桥梁、车库、陡坡、林地之前要预测整组碰撞轮廓。拖车撞击和轮胎磨损也需保存，不能因挂接/拆挂重置。

## 78.2 救援玩法

车辆陷入泥潭、车胎爆裂或发动机故障时，玩家可以选择：携带工具现场维修、卸货减轻负重、用绞盘在合适锚点缓慢拉出、呼叫附近受任务驱动的维修NPC协助、使用救援车牵引到据点。救援不能跨越不可能的地形与建筑墙体；若车辆被遗弃，其坐标和车内货物仍保留。

## 78.3 据点车库与工作区

玩家可建造停车位、带顶车棚、车库门、检查/维修工位、燃油存放点、轮胎架、工具柜、零件储物柜、电瓶充电器和基础车辆照明。使用第48章建筑系统安置结构，使用第51章电网供应车库照明、电瓶充电器、机械工作台；车库门或围栏可能被丧尸破坏。空间不足的据点不能让大型卡车通过标准住宅门洞。

## 78.4 任务与地图路径

委托任务包括寻找特定车辆、将药品送到诊所、从工业区拖回发电机、维修警车、打通被车辆堵塞的主路、救援抛锚货车、从异常区取回被遗弃的车辆。任务奖励由 `QuestManager` 单次结算，不在目标车后备箱无限生成奖励；被任务选中的实际车辆沿用既有世界实例。

# 79. 车辆升级、改装与技能解锁

## 79.1 改装原则

参考第46章枪械的“基础本体＋兼容改装”结构，但车辆使用独立部件槽位与车型兼容性，不共用枪械配件表。改装不会免费消除零件损坏；强化必须以材料、重量、成本、维护难度或油耗为代价。

| 改装方向 | 可装内容 | 收益 | 代价或限制 |
|---|---|---|---|
| 防护 | 钢制保险杠、车门防护板、窗防护网 | 减少撞击/抓挠损伤 | 增重、视野或油耗代价 |
| 运输 | 货架、后排座椅拆除、绑带、拖钩 | 运大型物资、牵引拖车 | 座位减少、重心变化 |
| 越野 | 越野胎、悬挂调校、底盘护板 | 山道、泥地性能提高 | 公路制动/舒适度妥协 |
| 隐蔽 | 低噪排气、遮光车内灯 | 减少部分环境暴露 | 高负载/高速仍产生噪声 |
| 照明 | 车顶灯、强光前灯 | 雾夜道路识别更好 | 电量负担及克苏鲁光感知风险 |
| 后勤 | 车载工具箱、急救模块、简易卧铺 | 救援、临时营地 | 消耗货厢/座位空间 |
| 电气 | 电瓶扩容、充电接口、报警系统 | 用电可靠性、设备扩展 | 维护难度、附加重量 |

## 79.2 解锁分工

机械技能在1—25级每次升级都会掌握新的拆件、底盘/发动机、复杂维修或机械工具维护能力；电力技能逐级提高车载灯、充电器、电路修复、报警和高阶电气组件的处理能力；制作技能逐级掌握货架、护板、车顶架与焊补；生存技能帮助识别道路、矿区和天气风险。配方同时需要实际工具、材料、工作台、车型兼容，而不是只看单一等级。

## 79.3 改装实例数据

每一个改装件拥有唯一物品实例与独立健康状态，装卸是“世界物品↔车辆部件槽”的原子事务。车辆改装完成后，3D模型按预定义挂点显示护板、货架、灯和轮胎变化；LOD模型必须与实际碰撞宽度相匹配，不能视觉上装了宽大保险杠而碰撞仍穿过墙体。

# 80. 载具与丧尸、克苏鲁、NPC、任务和基地防御

## 80.1 战斗及逃生定位

车辆负责战术移动和救援，不替代枪械或基地塔防。车辆可以撞击普通丧尸，但撞击积累车损；面对T3/T4克苏鲁时，车体速度、封闭车厢和灯光提供新的策略但不能无限免疫异常感知。某些固定型克苏鲁可以攻击行驶车辆的轮胎/灯具/窗户，区域型则依原有领地限制追踪车辆；离开领地与熄火不会直接删除其仇恨状态。

## 80.2 NPC辅助

守卫NPC可以坐车运送物资、在玩家停车后帮忙搬运限定物品、在据点提供有限机械协助。NPC不会自动刷满油箱、替玩家无上限修车或永久坐在驾驶席绕地图巡逻；任务需要的护送乘员由任务管理器分配独立ID。车辆内人员可能受伤、晕厥、恐惧或感染；医疗AI必须读取玩家和NPC各自真实状态，不能用车辆“整体生命”代替。

## 80.3 据点设施

主世界据点的自动哨塔只会依据自身电网、弹药和目标规则攻击；如果玩家把车停在枪线前，会挡住射线；照明和车灯可能提高敌人发现玩家的机会，不能让装甲车穿透据点围墙。车辆停在车库内，电池充电器工作时必须为同一物理电瓶写入电量；被克苏鲁破坏的车库门遵守共享建筑状态。

## 80.4 交通任务

任务可包含递送物资、载伤员撤退、维修抛锚车辆、清理事故道路、调查失踪救护车、取回颠倒世界中的车辆和样本。任务状态按照“接受→目标定位→有效运输/调查→结算→领奖”推进。运送任务通过**具体物品实例ID或合格物资标签＋一次性交付事务**验证；交付后物品必须真实转移而不是复制，领取奖励不重置车辆油量与库存。

## 84.1 节点和管理器职责

```text
WorldRoot/SharedWorld
└── VehicleRegistry                 # vehicle_id -> 唯一持久数据
    └── VehicleVisualActors         # 只实例化当前世界层可交互车辆

VehicleScene (RigidBody3D 或 VehicleBody3D)
├── CollisionShape3D
├── BodyVisuals/MeshInstance3D
├── EngineComponent
├── FuelComponent
├── BatteryComponent
├── WheelComponents
├── DoorComponents
├── StorageComponents
├── SeatManager
├── DamageZones
├── NoiseEmitter
├── LightEmitter
├── WeatherExposure
├── VehicleCameraAnchor
├── TowHitch
└── RiftTargetAnchorPoints

Managers (Autoload 或服务层)
├── VehicleManager               # 生成、实例状态、车钥匙、进出车辆
├── VehicleSimulationSystem      # 固定物理步/分区更新
```

避免创建第二份世界时间、第二份天气管理器或另一个背包系统。物理场景节点是运行时视图；持久数据由 `VehicleRegistry` 和 `SharedWorldState` 持有。进入另一世界后释放/重绑物理场景不会重建库存与车辆实例ID。

## 84.2 基本数据结构（资源与状态分离）

```gdscript
# VehicleDefinition (静态 Resource)
class_name VehicleDefinition
extends Resource
@export var definition_id: StringName
@export var seat_count: int = 4
@export var curb_mass_kg: float = 1200.0
@export var cargo_volume_l: float = 160.0
@export var max_payload_kg: float = 350.0
@export var fuel_capacity_l: float = 45.0
@export var valid_part_families: Array[StringName]

# VehicleInstance 建议保存为纯数据字典或自定义资源
# vehicle_id, definition_id, active_world_layer, transform,
# velocity, engine_state, ignition_state, fuel_l, battery_wh,
# parts_by_slot, cargo_container_ids, seat_occupants,
# tow_link_id, last_simulation_world_time, pending_transfer_id
```

`VehiclePartDefinition` / `VehiclePartInstance` 分离型号、兼容与耐久；`VehicleSeatState` 包含seat索引、乘员ID、是否系安全带、是否保留座位；`VehicleCargoContainerState` 存储唯一container ID与持有的物品ID；`RiftVehicleLatch` 存储rift ID、车辆ID、抓点、触手数量、抓取计时和反制进度。

## 84.3 相位转移事务接口

```text
request_vehicle_phase_transfer(vehicle_id, rift_id, target_layer)
  -> validate_not_already_transferring()
  -> validate_rift_level_and_flags()
  -> validate_vehicle_size_mass_and_towing_group()
  -> validate_occupants_and_quest_state()
  -> find_safe_target_transform_for_entire_vehicle()
  -> stage_transaction(pending_transfer_id, snapshot)
  -> lock_vehicle_controls_and_collision_authority()
  -> move_vehicle_and_occupants_as_one_group()
  -> switch_active_world_layer_and_environment()
  -> restore_actor_physics_and_camera()
  -> commit_transaction_once()
  -> notify_noise_ai_quest_and_save_systems()
```

此为系统级流程，不是可直接复制执行的完整脚本。必须确保阶段性异常、切场景失败和读档恢复都可以幂等重试或回滚。跨世界切换触发一次 `vehicle_world_layer_changed(vehicle_id, from_layer, to_layer, transfer_id)` 信号，重复 `transfer_id` 不再次结算。

## 84.4 大世界三级模拟

**近距离**：完整轮胎/车身物理、灯光、声音、乘员动画和碰撞（玩家驾驶或附近追踪）。**中距离**：停止复杂轮胎求解，按路线和当前速度/威胁低频更新少量NPC与任务车（默认单人世界多为空车）。**远距离**：只保存车辆最后位置、世界层、燃料/电瓶与事件计时，非任务车辆通常静止。不可按帧在远处自动消耗所有停放汽车的油量；仅仍运转中的车辆以世界时间分段结算怠速燃油、充电和噪声影响的区域摘要。

当玩家进入车内并高速跨区时，按行驶方向前置加载道路与碰撞，保持玩家前方预加载距离；镜头自由旋转时仍覆盖可能驾驶的前方空间。导航和车辆物理不应因区块刚刚卸载而让车坠入地面下方。

# 85. 载具UI、首版范围、平衡参数与验收清单

## 85.1 UI和反馈

驾驶界面显示速度、燃油/预计行驶余量、发动机工作状态、电瓶与关键故障；普通驾驶只显示必要信息，按键展开详细车辆状态面板。维修面板使用可旋转的车辆轮廓、部件部位、耐久、材料和技能条件；货物面板沿用网格背包格式并标明“后备箱/座位/货斗/拖车”。地图上可标注玩家已经检查过的车辆、燃油站、维修店、可通行道路和可携车穿越的裂隙。

车捕裂隙提示按阶段呈现：路面异动与雷达/仪表干扰→车身被触手缠绕、方向受力、进度和挣脱提示→相位转场→车辆仪表恢复、周围环境变异→地图标注当前世界层和返回路线。禁止把车捕表现仅写成黑屏闪现或无预兆传送。

## 85.2 最小可玩载具闭环

在现有M0—M12里程碑内安排：M4实现轿车驾驶、停车上下车、油量、电瓶和基本事故；M5加入维修零件与后备箱网格装卸；M7完成车库、电瓶充电与灯光/天气的联系；M8加入NPC上车与一个运输任务；M9完成车灯对克苏鲁特殊感知的联动；M10完成R4/R5车捕裂隙、整车转层与返程；M11验证跨区高速加载和拖车保存；M12处理大型交通与异常压力测试。摩托车、重型货车、全套改装配件和车辆拖车可逐阶段补充，但其数据接口从首次实现就保留。

## 85.5 调试界面与测试地图

建立可切换的载具调试HUD：车辆ID、当前世界层、车速、加速度、轮胎抓地、当前油耗、车重、乘员列表、座位预约、当前噪声半径、所在区块、零件故障原因及 `last_simulated_at`。裂隙调试层显示等级/形态、车捕开关、质量与包络检查、触手抓点、牵引力、捕获状态、当前事务ID和两层落点检查结果。最少准备六个可重复测试场景：车库与停车场、城市窄巷与路障、泥地/冰雪坡道、尸群道路、R4小车裂隙、R5带NPC与拖车的裂隙。

## 85.6 功能一致性原则

载具燃油、电瓶、零件、装备、货物与建筑状态都属于持久共享世界；只有车辆实际可驾驶的物理存在归属于当前活跃世界层。十项技能、七项状态、天气与电网均被复用；不额外创造驾驶技能、不做“车辆专用感染值”。所有跨世界相关操作遵守统一世界时间、唯一ID、事务提交、异常回滚、世界层敌人隔离和人物返回保底规则。
