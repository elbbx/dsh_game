# M10｜世界区块流送、LOD和异步装配——独立可执行设计书

> **定位：**本文件先给本模块的完整可执行设计与对应数据，再附106章原规划中属于本模块的条款。表中数值为初始游戏平衡配置，非已测试结论。

## 1. 玩家体验与系统边界

64m块建议；基于玩家车辆速度预测加载，资源准备与主线程装配分离。本模块不得绕过物品所有权、世界层身份、世界时钟和全局事件幂等机制。

## 2. 完整业务处理链

1. **根据观察者计算interest set**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
2. **请求资源异步加载**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
3. **主线程限预算实例化场景**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
4. **激活导航/物理/敌人**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
5. **卸载前冻结并保存差异**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。

## 3. 模块专属规则、数值逻辑与边界

### 流送状态机
`UNLOADED→REQUESTED→DATA_READY→ASSEMBLING→ACTIVE→SLEEPING→SAVING→UNLOADED`。以64m×64m为候选逻辑区块；资源预取3—5块、模拟激活近区1—2块，实际距离由车辆速度和设备性能调整。绝对禁止在卸载时丢弃共享态；卸载前先冻结交互与事务、写状态差异、序列化敌人及车辆位置、解除导航RID、最后释放Node。关键交互期间延后卸载。

## 4. 运行时数据与职责

- **定义资源**：`10_Definition`：保留静态属性、参数上下限、版本号和关联ID。
- **实例状态**：`10_InstanceState`：保留instance_id、world_layer、last_tick、state_version及本模块运行字段。
- **动作请求**：`10_ActionRequest`：actor_id、target_id、requested_time、payload、event_id。
- **写入策略**：本模块仅写其负责的实例字段，对其他模块通过事件和接口请求变更。

## 7. 操作失败与回滚

- 当资源不足、目标不可达、角色处于不允许动作的状态时，返回明确错误码，不消耗物品。
- 如果跨区块或跨世界转移时目标场景未准备好，延后提交并保持唯一旧实例。
- 读档重放已提交事件应跳过重复event_id；未提交事件恢复到可重试状态。

## 8. 模块级验收场景

- [ ] 高速行驶前方无空洞。
- [ ] 离开区块后物资状态保留。
- [ ] 低内存、高速跨区、读档中断、异步资源未就绪和断电情形下行为有定义。
- [ ] 模块对外暴露的数据接口写成独立测试，不只依靠目视测试。

## 资源与接口要求
- 数据表使用UTF-8 CSV/JSON，字段包含ID、名称、数值、互斥与依赖；数值均为首轮测试值。
- 跨系统事件携带`event_id`以支持重复消息幂等处理；世界层共享状态不得重复实例化。
- 离线/卸载结算用绝对世界时钟；Node场景树增删应在主线程执行。
- 玩家移动与疾跑不因普通UI操作暂停；敌人照常感知玩家。

## 区块流送细节
- 水平区块推荐64m×64m；环境层/实体层/碰撞/导航分别加载，矿洞使用更小的局部可修改块（如16m）；道路跨区块边界通过边缘锚点对齐。
- 以玩家与快速车辆的预测位置为中心：近距高精度、次级低精度、远距纯数据。预取方向向量 = 当前速度 × 预测秒数，最大预取距离配置上限，避免速度过高加载爆炸。
- 区块状态：UNLOADED → REQUESTED → DATA_READY → INSTANTIATING → ACTIVE → COOLING → SERIALIZING → UNLOADED；所有异步响应携带generation_token，失效请求丢弃。
- 每帧实例化预算（如2—5ms），优先地形碰撞与道路再装饰；LOD按对象的重要度排序，安全缺失时暂停驾驶入口而不是让车掉进虚空。
- 卸载先快照实体数据和已确认事件，等待写盘确认再销毁Node；活跃AI迁出时根据唯一ID映射到PopulationCell。
- 同一chunk的主世界与颠倒世界引用同一共享地形和建筑差量，只切换渲染/导航敌人生态层；车辆只在active_world_layer中实例化。

# 2. 世界与地图结构

## 2.1 地图定位

地图采用大型开放世界，建议由多个可独立加载的区域组成。区域之间通过道路、森林、桥梁、隧道和特殊通道连接。

建议第一阶段规划六类区域：

  -------------------------------------------------------------------------------------
  区域       主要建筑与地点             主要资源                     主要威胁
  ---------- -------------------------- ---------------------------- ------------------
  居民区     独栋住宅、公寓、便利店     食物、衣物、日用品、工具     普通丧尸

  商业区     超市、餐厅、酒店、商场     食物、药品、日用品           尸群、特殊丧尸

  工业区     工厂、仓库、维修站         金属、机械零件、燃料         装甲丧尸

  医疗区     医院、诊所、实验室         药品、医疗工具、研究资料     异化丧尸、寄生体

  军事区     军营、武器库、地下设施     枪械、弹药、防护装备         装甲丧尸、异教徒

  异常区     污染森林、遗迹、地下祭坛   异常样本、遗物、神秘学资料   中高级克苏鲁生物
  -------------------------------------------------------------------------------------

## 2.2 世界时间

世界应有昼夜变化。昼夜影响能见度、普通丧尸活动体验、克苏鲁光源机制和玩家行动策略。

-   白天：更适合搜刮、道路移动和建筑外围观察。
-   夜间：能见度降低，手电筒等光源变得重要，同时可能触发高级克苏鲁的光源仇恨。
-   室内：由窗户、门、室内灯具和手持光源共同决定照明。
-   天气：动态晴、阴、雨、雷暴、风、雾及季节性雪/寒潮，并实际影响玩家、敌人感知、建筑遮蔽和太阳能；详见第43章。

### 天气与昼夜的玩法关联
世界时间统一驱动天气、温度、湿润程度、风、可见度和太阳能发电。晴、阴、雨、暴雨、雷暴、雾和季节性雪天气在第43章完整规定。天气同时作用于玩家体温相关状态效果、敌人视觉/听觉、搜索声音传播、地面湿滑、照明和据点发电；不得只做粒子特效。主世界与颠倒世界共用时间，颠倒世界通过独立环境覆层呈现异常天气，不复制可搜刮世界物体。

## 2.3 区域污染等级

区域污染作为独立世界参数，与玩家七项生存状态分别保存。

  等级   环境表现                 玩法影响
  ------ ------------------------ --------------------------
  0      普通环境                 无持续异常影响
  1      微弱异响、偶发异常影像   少量精神压力
  2      雾气、环境细节异常       T1、T2出现概率提高
  3      空间与光照异常           T3开始出现
  4      高度污染、异常生态       T4可能出现，特殊事件增加

区域污染可以长期存在，也可以通过剧情、调查或特定事件改变。

extends Resource

# 22. 主世界与颠倒世界的双层架构

## 22.1 三类数据

两个世界的数据应分成三类：

  数据类别             是否共享   示例
  -------------------- ---------- ----------------------------------------
  共享世界实体数据     是         建筑、门窗、家具、容器、物资、载具持久数据
  世界层专属环境数据   否         天空、雾、光照、材质覆盖、异常视觉效果
  世界层专属敌人数据   否         丧尸、克苏鲁、敌人位置、仇恨、巡逻状态

玩家数据属于全局共享数据，玩家切换世界时沿用同一个角色实例和同一套背包数据。车辆也只有一份共享状态，但实际可驾驶、可碰撞的载具属于单一 `active_world_layer`；相位转移通过第81—84章的事务切换所属世界层。

## 22.2 世界空间映射

两个世界采用完全相同的坐标系：

`MainWorldPosition == InvertedWorldPosition`

同一栋建筑在两个世界中：

-   位置相同。
-   尺寸相同。
-   楼层相同。
-   房间布局相同。
-   门窗位置相同。
-   家具位置相同。
-   物资容器位置相同。

建筑和家具保持对应坐标，环境外观通过材质覆盖、腐化结构和附着物变化呈现。

`SharedWorld`保持同一份运行实例；切换世界时更新世界层、环境表现和敌人集合。

## 22.4 切换世界的基本流程

1.  锁定玩家输入，进入过渡状态。
2.  保存玩家当前坐标和朝向。
3.  确认目标世界层及目标裂隙位置。
4.  切换世界层状态。
5.  隐藏或停用当前世界层专属敌人。
6.  启用目标世界层专属敌人。
7.  切换环境、光照、材质覆盖和特效。
8.  将玩家放置在目标裂隙安全位置。
9.  恢复玩家输入。
10. 继续运行共享世界状态。

世界切换通过世界层切换和共享状态恢复完成，地图实体和已搜刮物资沿用原有数据。

# 23. 世界数据同步规则

以下对象在两个世界中共用同一份状态：

  对象         同步规则
  ------------ ------------------------------------
  地形与道路   坐标、地形结构完全一致
  建筑         外部结构、楼层、房间和碰撞结构一致
  门           开关状态、锁定状态、破坏状态一致
  窗户         完整、破碎、封堵状态一致
  家具         位置、旋转、移动和破坏状态一致
  容器         容器内容、已搜刮状态一致
  物资         是否存在、所在位置、数量一致
  车辆         数据/货物/耐久/燃油唯一；实际驾驶实体仅激活于active_world_layer，见第83章
  发电机       位置、燃油、开关和耐久状态一致
  玩家建造物   建造、升级和破坏状态一致
  地面物品     拾取、丢弃和移动状态一致

例如：

玩家在主世界打开某个住宅的后门，进入颠倒世界后，这扇后门仍然保持打开。

玩家在颠倒世界搜刮一个厨房抽屉，返回主世界后，这个抽屉也必须保持已搜刮状态。

玩家在颠倒世界打碎一扇窗户，主世界对应位置的窗户也必须是破碎状态。

## 23.2 物资防重复规则

物资必须拥有全局唯一的实体 ID。

例如：

``` text
container_id: house_014_kitchen_drawer_02
item_instance_id: item_00008342
```

同一容器使用全局唯一ID和共享物资列表，两个世界读取同一份容器状态。

正确逻辑：

1.  地图初始化时，根据固定种子生成容器物资。
2.  生成结果写入共享世界状态。
3.  两个世界显示同一份容器数据。
4.  玩家在任意世界拾取物品，物品从共享世界状态中移除。
5.  切换世界后，另一个世界对应位置读取更新后的共享状态，保持物品已拾取结果。

## 23.3 玩家背包同步

玩家背包是全局唯一数据：

-   玩家在颠倒世界拾取的物资，返回主世界后仍然在背包中。
-   玩家在颠倒世界消耗的弹药记录在全局背包数据中，返回后保持消耗结果。
-   玩家在颠倒世界受到的伤害会保留。
-   玩家在颠倒世界消耗的食物、水和医疗用品记录在全局物品状态中，返回后保持当前数量。
-   玩家在颠倒世界产生的体力、疲劳和SAN变化会保留。

玩家背包和角色数据由全局PlayerState统一管理，世界切换只更新所在世界层和坐标。

## 23.4 敌人数据不同步

敌人属于世界层专属实体：

  敌人           主世界               颠倒世界
  -------------- -------------------- ------------------------------
  普通丧尸       主世界丧尸生态       颠倒世界使用独立克苏鲁生态层
  特殊丧尸       主世界特殊丧尸       颠倒世界使用独立克苏鲁生态层
  T1观察者       可以按区域规则出现   可以出现
  T2异常潜伏体   可以出现             可以出现
  T3狩猎者       可以出现             可以出现
  T4高级猎食者   高污染区域出现       可以出现，权重更高
  T5领域守护者   固定事件或特殊区域   固定事件或特殊区域

主世界丧尸保留独立世界层状态；玩家进入颠倒世界期间，丧尸使用区域简化模拟，玩家返回后恢复对应活动状态。

两个世界按世界层管理敌人生态；跨越裂隙的特殊生物通过专属能力和事件配置实现。

## 23.5 时间同步

两个世界使用同一套世界时间。

玩家在颠倒世界停留期间：

-   世界时间继续流逝。
-   玩家饥饿、口渴、疲劳和卡路里收支继续计算。
-   主世界丧尸可以使用低频模拟更新。
-   主世界容器和建筑沿用共享实体状态，保留已搜索、破坏和交互结果。
-   颠倒世界敌人继续按照其世界层规则活动。

世界时间和玩家生存状态在世界切换期间持续推进，远距离区域事件使用低频模拟。

# 52. 双世界、敌人及天气的交互规则

## 52.1 数据共享矩阵

| 系统/数据 | 主世界与颠倒世界 | 规则 |
|---|---|---|
| 建筑轮廓、门窗、家具、拆改结构 | **共享** | 同一实体ID，同一当前状态 |
| 容器、物品实例、任务道具 | **共享** | 任一侧拾取后另一侧不可再次拾取 |
| 玩家七项状态、技能、体型、装备 | **共享同一角色** | 切换时连续保存，感染药物不重置 |
| 发电机、太阳能板、电池、中继器、线路、燃料 | **共享** | 一张实际电网，不进行双重结算 |
| 车辆及车内货物/零件 | **共享一份持久数据** | 当前活跃世界层仅实例化一辆可驾驶车，载具穿越见第83章 |
| 当前实际照明呈现 | 分世界层表现 | 共享开关/供电条件，但视觉特效可不同 |
| NPC及岗位实体 | 仅主世界默认激活 | 不在颠倒世界复制驻守者 |
| 丧尸 | 仅主世界生态 | 颠倒世界无普通丧尸刷新 |
| 克苏鲁 | 按世界层实例保存 | 两侧不同活动、感知、血量实例 |
| 天气与世界时间 | 时间共享，气候基础共享 | 颠倒世界可使用异常天气视觉覆层 |
| 异常污染/关注度/SAN | 依据原有归属 | SAN属于玩家，关注度独立，区域污染按区域 |
| 裂隙入口、出口与配对 | 独立裂隙系统 | 保证至少有一条有效返回路线 |

## 52.2 建造和世界同步中的特殊情况

玩家在主世界架设屋顶、围墙、陷阱和中继器后，进入颠倒世界看到对应空间实体。因为屋顶破坏会影响降雨遮蔽，故任一世界对共享屋顶的改动会同时影响另一侧。世界层不允许对同一共享实体分别保持矛盾的门状态/物资数量；如果特定剧情需要异常幻影家具，应定义为**不参与共享库存和实际碰撞的视觉对象**。

## 52.3 任务与共享物资防重复

任务目标需带 `quest_instance_id`，从世界中的普通容器搜刮出所需物资时，只检查已有物品实例，不重建容器库存。任务专用道具只能生成一次，拥有唯一实例ID，领取时执行“标记任务物品已取走”的持久化事务。NPC奖励同样用唯一领奖事务ID；切换主世界/颠倒世界不重新初始化任务进度。

## 52.4 克苏鲁与防御设施

固定型、区域型和伏击型克苏鲁继续遵守第28章的边界和仇恨逻辑。自动哨塔对敌对克苏鲁是否有效取决于实体配置中的 `targetable_by_turret` 和伤害抗性；T1观察者不默认成为可射击目标。克苏鲁特殊感知不能因为玩家装了“潜行配件”就被完全关闭。探照灯的光感知威胁与NPC、玩家使用的光源遵循相同环境判定规则。

## 52.5 天气叠加顺序与平衡护栏

天气分别修正玩家移动、敌人视觉/听觉、太阳能发电，不直接修改异常关注度与NPC任务难度。重度感染、寒冷、负重与疲劳共同作用时，应采用**乘算并限制最终下界**：例如最终移动速度不得因一般可恢复debuff低于基础速度的35%（骨折等特殊伤势可以另外设计行动限制）。这样多系统叠加仍有可操作的逃生空间。

## 52.6 玩家长期循环样例

第1日，玩家在雨天搜索住宅得到食物、电器零件和基础手枪，遭丧尸抓伤感染+4，使用消毒物资处理伤口并寻找抗生素。第2日，玩家把房屋改为据点，搬动柜子、加固门、造基础工作台。第3日，玩家接受工程师恢复供电任务，找回发电机并安装一台中继器，灯亮但燃料有限。第4日，玩家拿到太阳能板和锂电池，白天充电、夜间供照明。第5日，玩家在附近搭建瞭望塔，给NPC配置少量弹药，抵御小尸群。之后，高污染区探索带来克苏鲁关注度提升，玩家仍需穿过裂隙、进入颠倒世界研究异常，并不能靠自动哨塔代替探索。

## 53.4 电网拓扑与负载结算伪代码

```gdscript
# 示意伪代码；实际按项目Resource与节点接口实现。
func recompute_grid_components() -> Array:
    var visited := {}
    var components := []
    for node_id in power_nodes.keys():
        if visited.has(node_id):
            continue
        var comp := bfs_valid_links(node_id, visited)
        components.append(comp)
    return components

func settle_component(component, delta_world_hours: float) -> void:
    var generation_kw := calculate_sources(component, weather_manager.current_state)
    var relay_kw := calculate_active_relay_usage(component)
    var available_kw := max(0.0, generation_kw - relay_kw)
    var storage := collect_storage(component)

    var consumers := get_consumers_by_priority(component)
    for consumer in consumers:
        if can_cover_load(available_kw, storage, consumer.power_kw, delta_world_hours):
            available_kw = serve_consumer(consumer, available_kw, storage, delta_world_hours)
        else:
            consumer.set_powered(false)

    charge_storage_with_surplus(storage, available_kw, delta_world_hours)
    settle_fuel_and_condition(component, delta_world_hours)
```

必须防止在环形连接中重复枚举电源；`can_cover_load()` 应考虑电池最大放电功率和剩余kWh，`charge_storage_with_surplus()` 应考虑最大充电功率、效率与容量。代码采用较长世界时间增量时，需要按光照/燃料变化分段结算。

## 53.5 感染结算伪代码

```gdscript
func apply_zombie_hit(attack_id: String, infection_amount: float, mitigation: float) -> void:
    if processed_attack_ids.has(attack_id):
        return
    processed_attack_ids[attack_id] = true
    var actual_gain := max(0.0, infection_amount * (1.0 - mitigation))
    infection_value = clampf(infection_value + actual_gain, 0.0, 100.0)
    refresh_infection_stage()

func update_infection(delta_world_hours: float) -> void:
    var growth := get_progression_rate(infection_value, active_treatments)
    var healing := get_treatment_rate(active_treatments)
    infection_value = clampf(infection_value + (growth - healing) * delta_world_hours, 0.0, 100.0)
    refresh_infection_stage()
```

攻击去重集合应按短期时间窗或持续攻击生命周期清理，避免无限增长；已发生的世界持久事件用事务ID防重复，普通战斗攻击ID不必永久保存在存档内。

func rebuild_weapon_stats(weapon: WeaponInstance) -> Dictionary:

## 53.7 世界加载、AI与网络性能

天气可按气候区缓存，雨滴效果只在摄像机附近生成；电网仅在拓扑变化时重算连通分量，运行时按固定周期分配电力；远距离哨塔/NPC按时间切片进行概率战斗结算；室内检测用空间区域与上方遮挡，不对每个粒子逐点射线检测；建筑建造与拆除后局部标记导航区为dirty，批量刷新。角色感染、药物和电池运转采用世界时间戳而非UI帧时间。

## 53.8 一致性顺序

加载游戏时依次：静态定义数据库→世界时间/天气→共享建筑与容器→建造家具与电力节点/线路→玩家背包和武器实例→角色感染/技能→NPC及任务→电网拓扑恢复→世界层表现与敌人实例→UI与远距结算。先完整恢复电网，再让哨塔与工作台开始运行；先恢复任务物品唯一ID，再加载可交互容器，避免读档一帧内重复生成物资。

# 94. 挖掘地形与建筑道路载具的交互

## 94.1 挖掘边界与结构保护

- 建筑地基和预制地下室通过结构支撑代理参与稳定计算；下方可挖区域失去足够支撑会逐步受损，先给出裂纹和危险提示。
- 主线任务建筑、不可替代的NPC建筑、主干桥梁锚点和至少一条裂隙返程通路需设置保护区或可修复的安全机制。
- 玩家建造的地板、矿道木支柱、临时梯子和井口护栏可提供明确的支护效果；拆除构件后按局部依赖计算。
- 在普通道路下开掘只对可挖掘区生效；已保护的主干路基不能被低级镐头从地下随意掏空。
- 矿道塌方和地形挖空不能让服务器式事务中的NPC、车辆、货物或玩家落入未加载空间。

## 94.2 导航和敌人进出

采掘改变可站立表面后触发局部导航区域重建，并校验矿道坡度、通道最小宽度和楼梯/梯子连接。普通丧尸可以在满足体型和通行规则的矿道里寻路与调查声音；狭窄洞口会形成堵塞与撤退战术。克苏鲁使用原有区域边界和追踪规则，不能穿越真实岩层。远距离矿道NPC/敌人按事件摘要模拟，不为所有地下空间常驻完整寻路。

## 94.3 载具与开采地点

采矿区、采石场和林地可以设置车辆停靠位、木料装卸处和临时矿石箱。车辆能在玩家挖出的合法道路上行驶时需要足够宽的碰撞通道、坡度和高度；不能因为有一条挖出来的狭窄洞穴就允许SUV直接穿过。重载使车辆油耗与悬挂损耗变化；湿泥坡增加陷车风险。车内矿石、木料、工具与其他货物共用第75章真实库存，不创建“矿石专用无限车仓”。

## 94.4 地图标识与路径记忆

玩家可标记矿口、剩余储量预估、坡道、井口危险、采石场与林业点。已探索矿道在本地地图以简化剖面/层级信息显示，而不必须绘制全3D地下透视地图。洞穴入口和出口对应稳定世界坐标。已有矿洞路径在载入时必须恢复，不允许读档让出口变回实心石壁。
