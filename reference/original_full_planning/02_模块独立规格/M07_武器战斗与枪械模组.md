# M07｜武器、弹道、配件、噪声与近战——独立可执行设计书

> **定位：**本文件先给本模块的完整可执行设计与对应数据，再附106章原规划中属于本模块的条款。表中数值为初始游戏平衡配置，非已测试结论。

## 1. 玩家体验与系统边界

三武器槽；武器本体+配件兼容图；独立弹匣及枪械条件。本模块不得绕过物品所有权、世界层身份、世界时钟和全局事件幂等机制。

## 2. 完整业务处理链

1. **装配枪身/弹匣/瞄具/枪托等槽位**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
2. **计算综合属性与合法性**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
3. **射击命中/散布/护甲伤害**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
4. **生成声音事件传给人口池**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
5. **近战弧线与部位命中**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。

## 3. 模块专属规则、数值逻辑与边界

### 武器核心
`weapon_core` 决定平台口径、发射模式和可用配件槽；瞄具、枪口、握把、枪托、弹匣、前护木有兼容标签，改装实时重新计算重量/后坐力/操控/精度/噪声。弹匣和子弹独立实例，装弹消耗物品。每次射击生成损伤、弹壳、光、声音四种事件；声音转交NoiseBus，不能通过场景播放音效替代丧尸声源事件。

## 4. 运行时数据与职责

- **定义资源**：`07_Definition`：保留静态属性、参数上下限、版本号和关联ID。
- **实例状态**：`07_InstanceState`：保留instance_id、world_layer、last_tick、state_version及本模块运行字段。
- **动作请求**：`07_ActionRequest`：actor_id、target_id、requested_time、payload、event_id。
- **写入策略**：本模块仅写其负责的实例字段，对其他模块通过事件和接口请求变更。

# 8. 战斗、武器与物品耐久

## 8.1 武器类别

-   手枪。
-   冲锋枪。
-   步枪。
-   霰弹枪。
-   狙击枪。
-   斧、锤、棍棒、刀具等近战武器。
-   特殊异常工具。

## 8.1A 模组化枪械原则
所有常规枪械使用“基础枪身 WeaponBase + 有兼容性限制的配件槽 AttachmentSlots + 配件实例”构成。基础枪身决定武器类别、弹种和基准耐久；枪口、光学、握把、枪托、弹匣、护木及战术附件改变数值和外观。配件是能够搜刮、交易、拆卸和存档的独立物品，数值变化由统一公式结算。改装工作台和野外有限拆装规则详见第46章。

## 8.2 枪械机制

参考塔科夫式装备管理：

-   弹匣独立管理。
-   子弹型号独立。
-   枪械支持配件。
-   武器存在耐久度。
-   装填需要时间。
-   可以检查枪械状态。
-   枪械可能发生故障。
-   不同弹药对护甲和怪物具有不同效果。

## 8.2A 持有武器与快捷切换

远程和近战武器共用三个实际武器装备槽，而非各自持有三把。快捷键1（远程）和2（近战）从三槽中过滤出对应武器实例：仅一把即直接持握；有两把或三把时使用鼠标三扇区轮盘选中，确认后只执行切换，不自动攻击。轮盘空扇区禁用。被放在主背包的枪械必须手动装备后才能快捷切换。持有武器时左键正常执行攻击，除非界面输入正接管鼠标。

## 8.3 声音事件

所有会发声的动作向声音系统提交事件：

-   声音类型。
-   声音强度。
-   传播距离。
-   持续时间。
-   声音来源位置。
-   环境遮挡。

枪械、爆炸、汽车警报和玻璃破碎形成声音事件并吸引丧尸；克苏鲁根据视觉、光源和异常感知建立目标。

克苏鲁受到直接命中时仍然会触发受击反应。

# 46. 模组化枪械、枪械本体和配件

## 46.1 整体设计

参考《ZERO Sievert》“持有基础枪械、在工作台更换兼容配件、根据模组组合改变属性与观感”的思路。游戏所有常规枪械由**枪身基础件**和一组可更换**模组槽位**构成。基础枪械本身是可开火、可搜刮、可维修的完整物品；模组不是必须的，玩家能把搜来的配件逐步装上，不需要反复打造整把枪。

模组化提供四种决策：发现好枪身还是好模组、战斗属性取舍、背包重量取舍、珍贵配件是否带出风险区域。改装系统应兼容原有弹匣/子弹/耐久/重量/网格背包系统。

## 46.2 武器本体与槽位

| 枪身类别 | 默认配件槽位（按型号变化） | 战术特色 |
|---|---|---|
| 手枪 | 枪口、瞄具、弹匣、战术附件 | 轻便，槽位较少 |
| 冲锋枪 | 枪口、瞄具、弹匣、枪托、前握把、战术附件 | 近距离快速战斗 |
| 突击步枪 | 枪口、瞄具、弹匣、枪托、握把、护木、战术附件 | 可塑性强、用途广 |
| 霰弹枪 | 枪口、瞄具、枪托、供弹组件、战术附件 | 近距离高冲击，配件较少 |
| 精确射手/狙击枪 | 枪口、瞄具、枪托、弹匣、支撑配件 | 远距离稳定与重量权衡 |

每个型号通过 `slot_mask` 和 `compatibility_tags` 定义实际可用槽位，不要求所有型号都能安装每种组件。特定一体式结构的槽位可锁定；空槽提供基础外观与默认数值。

## 46.3 配件类别与属性

| 配件 | 提供的主要属性 | 典型代价 |
|---|---|---|
| 光学瞄具 | 视野辅助、瞄准放大、目标辨识 | 重量和瞄准速度 |
| 枪口装置 | 射击声音、后坐、火光表现 | 重量、耐久、特定兼容限制 |
| 枪托 | 后坐稳定性、持枪晃动 | 重量和操作速度 |
| 握把/前握把 | 人体工学、稳定性 | 占用配件槽 |
| 弹匣 | 容量、装填时间、重量 | 弹药消耗和背包占用 |
| 护木 | 战术附件插槽、外观 | 额外重量 |
| 战术手电/激光模块 | 夜间照明、近距离辅助 | 电量/能量消耗、光源暴露风险 |
| 枪管组件（允许的型号） | 弹道表现、长度与重量 | 灵活性和维修成本 |

重要联动：战术手电若直接照射具有光源感知的克苏鲁，可以触发原有光源仇恨；消音模组只降低丧尸对枪声的响应距离，不让武器完全无声。不同模组组合不应在全部指标同时碾压基础武器。

## 46.4 动态属性结算

基础属性：`damage`、`fire_rate`、`recoil`、`ergonomics`、`accuracy_spread`、`reload_time`、`noise_strength`、`durability`、`weight`、`inventory_size`、`attachment_slots`。配件附加值集中计算：

`final_stat = clamp((base_stat + Σflat_mod) × (1 + Σpercent_mod), minimum, maximum)`

`final_weight = base_weight + Σattachment_weight + loaded_ammo_weight`。

例如基础步枪后坐参数100，枪托-10、握把-6，改造后为84；同时增加0.45kg，导致负重更高。所有界面显示“改装前→改装后”的净变化，禁止重复装卸造成属性永久累加；每次由基础数值重新派生最终属性。

## 46.5 改装台与实际流程

1. 玩家拾取基础步枪、瞄具、握把和配件零件；模组占据网格背包或仓库空间。
2. 走到武器工作台，选择一把枪械实例，进入槽位视图。
3. 拖入配件，界面判定武器类型、槽位类型、兼容标签、配件冲突和工具等级。
4. 预览装配后的枪械外观、射击属性、重量、背包格子与耐久。
5. 确认后一次性提交物品转移：取走新配件、退回旧配件、更新枪械组合实例。
6. 退出工作台后，实际模型根据槽位装载独立低模子组件；弹匣和子弹仍由原背包与战斗系统持有。

在野外允许手电、简易瞄具等部分配件快捷更换，但需要安全时间与工具；复杂改装必须在工作台进行，战斗中禁止瞬间更换配件。

## 46.6 维修、配件品质与获取

枪身耐久与主要配件耐久独立保存；损坏的瞄具降低视野辅助，损坏枪身影响卡壳概率。维修需零件、工具、技能，拆卸回收不无限提供材料。模组来源：枪店、警察局、军事基地、NPC交易、任务奖励、敌人掉落、拆解战利品。枪械3级可以改装简易瞄具，6级掌握基础握把，11—14级逐步掌握枪口配件、照明和弹药装配，15级具备基础枪械维修台知识，20级可制造高级维修套件，25级掌握复杂模组组合；各等级仍逐级提供额外枪械能力。现成枪械和基础附件可以通过搜刮或NPC服务使用，高级自制配件需枪械/制作/机械跨技能条件。

## 46.7 数据与存档

枪械实例需保存：`weapon_instance_id`、`weapon_base_id`、`base_condition`、`attachments: Dictionary[slot_id, item_instance_id]`、`magazine_instance_id`、`chambered_ammo`、`paint_or_skin_id`（选用）。配件不作为枪械定义模板的一部分永久复制；配件实例只能属于一个位置/容器。枪械模型由低模主体与装配点合成，Godot `Marker3D` 为模型槽位提供挂载点，所有改装先经过服务器式单机事务校验再刷新外观。

## 46.8 验收清单

不同型号不兼容附件拒绝安装；拔下配件归还背包；枪身无配件也能作战；不同模组改变属性和3D外观；读档后组件与弹药不复制；配件增加重量并改变可用背包格子；照明附件对克苏鲁发挥原有光感知机制。
