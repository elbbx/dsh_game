## 1. 玩家体验与系统边界

共享建筑容器/植被资源，敌人按层独立；R4/R5可拉入车辆。本模块不得绕过物品所有权、世界层身份、世界时钟和全局事件幂等机制。

## 2. 完整业务处理链

1. **评估裂隙生成锚点和预警**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
2. **触手判定遮挡与抓取**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
3. **准备跨层TransferTransaction**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
4. **搬移整车乘员与货物引用**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。
5. **保障返回裂隙和断点恢复**：输入由唯一对象ID、世界层、当前世界时钟以及必要的物品/技能/位置构成；先验证目标、条件和容量，再发布带event_id的动作事件；最后在统一状态记录中提交变更，更新显示并记录异常日志。

## 3. 模块专属规则、数值逻辑与边界

### 双世界事务
共享门窗、破坏、物资、矿脉和载具状态只有一份；实体具有`current_layer`，不能两个层同时活动。高等级裂隙捕获车时：冻结交互→验证车辆/乘员/拖车与落点→事件日志预写→改变层所有权→在目标层激活→提交日志。若主线程途中崩溃，读档按transaction_id回滚或完成。返程必须有足够宽、地形可放车的出口。

## 4. 运行时数据与职责

- **定义资源**：`20_Definition`：保留静态属性、参数上下限、版本号和关联ID。
- **实例状态**：`20_InstanceState`：保留instance_id、world_layer、last_tick、state_version及本模块运行字段。

- **写入策略**：本模块仅写其负责的实例字段，对其他模块通过事件和接口请求变更。

## 7. 操作失败与回滚

# 21. 颠倒世界系统总览

## 21.1 系统定位

新增一个与主世界空间结构一致的平行世界，暂定名称为**颠倒世界（Upside
Down）**。

颠倒世界是主世界空间数据的异常映射层。玩家可以通过主世界地表或建筑中的裂隙进入颠倒世界，也可以通过颠倒世界中的裂隙返回主世界。

核心规则：

-   两个世界使用相同的地图坐标、建筑布局和可交互物体数据。
-   建筑、家具、容器、物资、门窗、车辆和玩家改造状态保持同步。
-   玩家背包、装备、伤势、七项生存状态、技能和时间在切换世界时持续保留。
-   颠倒世界运行克苏鲁生态层，主世界运行丧尸生态层。
-   颠倒世界只刷新克苏鲁生物。
-   主世界保留普通丧尸生态，并可按原有规则刷新克苏鲁生物。
-   克苏鲁的AI、活动范围、刷新点和敌人状态可以按世界层分别保存。
-   裂隙是两个世界之间的通道，也是颠倒世界的主要进出方式。

## 21.2 设计目标

颠倒世界沿用主世界空间结构，玩家可以凭借熟悉的建筑和道路规划路线，同时体验不同环境与敌人生态。

玩家进入颠倒世界后，应该产生以下感受：

1.  熟悉的道路、房屋和房间仍然存在。
2.  建筑结构和物资位置没有改变。
3.  原本熟悉的安全路线变得危险。
4.  主世界中的丧尸威胁消失，但克苏鲁威胁明显增加。
5.  玩家能够利用熟悉的建筑结构、掩体和道路规划路线。
6.  玩家在颠倒世界搜刮、破坏或搬动物品，会同步影响主世界。

## 21.4 世界层定义

建议定义两个世界层：

  世界层     ID                 内容
  ---------- ------------------ ------------------------------------------
  主世界     `MAIN_WORLD`       普通环境、丧尸、部分克苏鲁、正常物资生态
  颠倒世界   `INVERTED_WORLD`   异常环境、克苏鲁、无丧尸

世界层决定当前环境效果和敌人实体集合；共享物体沿用统一身份和世界坐标。

## 21.5 颠倒世界视觉表现

颠倒世界保留主世界的空间结构，并使用独立环境表现：

-   天空和环境光呈现异常色调。
-   建筑表面出现腐化、菌丝、触须和异常附着物。
-   部分墙面、地面和天花板出现有机结构。
-   植被变暗、枯萎或呈现异常形态。
-   室内光照更弱，远处能见度降低。
-   空气中存在漂浮孢子、灰尘或微粒。
-   水面、玻璃和金属表面可以出现异常反射。
-   裂隙附近具有更强烈的空间扭曲效果。

颠倒世界通过环境、材质、光照和生态差异呈现空间异变，同时保持建筑空间、碰撞、楼梯和导航规则的可识别性。

颠倒世界的空间异变主要通过生态、光照、材质、氛围和异常规则呈现。

# 22. 主世界与颠倒世界的双层架构

## 22.1 三类数据

两个世界的数据应分成三类：

  数据类别             是否共享   示例
  -------------------- ---------- ----------------------------------------
  共享世界实体数据     是         建筑、门窗、家具、容器、物资、载具持久数据
  世界层专属环境数据   否         天空、雾、光照、材质覆盖、异常视觉效果
  世界层专属敌人数据   否         丧尸、克苏鲁、敌人位置、仇恨、巡逻状态

玩家数据属于全局共享数据，玩家切换世界时沿用同一个角色实例和同一套背包数据。车辆也只有一份共享状态，但实际可驾驶、可碰撞的载具属于单一 `active_world_layer`；相位转移通过第81—84章的事务切换所属世界层。

## 22.2 世界空间映射

两个世界采用完全相同的坐标系：

`MainWorldPosition == InvertedWorldPosition`

同一栋建筑在两个世界中：

-   位置相同。
-   尺寸相同。
-   楼层相同。
-   房间布局相同。
-   门窗位置相同。
-   家具位置相同。
-   物资容器位置相同。

建筑和家具保持对应坐标，环境外观通过材质覆盖、腐化结构和附着物变化呈现。

## 22.4 切换世界的基本流程

1.  锁定玩家输入，进入过渡状态。
2.  保存玩家当前坐标和朝向。
3.  确认目标世界层及目标裂隙位置。
4.  切换世界层状态。
5.  隐藏或停用当前世界层专属敌人。
6.  启用目标世界层专属敌人。
7.  切换环境、光照、材质覆盖和特效。
8.  将玩家放置在目标裂隙安全位置。
9.  恢复玩家输入。
10. 继续运行共享世界状态。

世界切换通过世界层切换和共享状态恢复完成，地图实体和已搜刮物资沿用原有数据。

# 23. 世界数据同步规则

## 23.1 必须同步的对象

以下对象在两个世界中共用同一份状态：

  对象         同步规则
  ------------ ------------------------------------
  地形与道路   坐标、地形结构完全一致
  建筑         外部结构、楼层、房间和碰撞结构一致
  门           开关状态、锁定状态、破坏状态一致
  窗户         完整、破碎、封堵状态一致
  家具         位置、旋转、移动和破坏状态一致
  容器         容器内容、已搜刮状态一致
  物资         是否存在、所在位置、数量一致
  车辆         数据/货物/耐久/燃油唯一；实际驾驶实体仅激活于active_world_layer，见第83章
  发电机       位置、燃油、开关和耐久状态一致
  玩家建造物   建造、升级和破坏状态一致
  地面物品     拾取、丢弃和移动状态一致

例如：

玩家在主世界打开某个住宅的后门，进入颠倒世界后，这扇后门仍然保持打开。

玩家在颠倒世界搜刮一个厨房抽屉，返回主世界后，这个抽屉也必须保持已搜刮状态。

玩家在颠倒世界打碎一扇窗户，主世界对应位置的窗户也必须是破碎状态。

## 23.2 物资防重复规则

物资必须拥有全局唯一的实体 ID。

例如：

``` text
container_id: house_014_kitchen_drawer_02
item_instance_id: item_00008342
```

同一容器使用全局唯一ID和共享物资列表，两个世界读取同一份容器状态。

正确逻辑：

1.  地图初始化时，根据固定种子生成容器物资。
2.  生成结果写入共享世界状态。
3.  两个世界显示同一份容器数据。
4.  玩家在任意世界拾取物品，物品从共享世界状态中移除。
5.  切换世界后，另一个世界对应位置读取更新后的共享状态，保持物品已拾取结果。

## 23.3 玩家背包同步

玩家背包是全局唯一数据：

-   玩家在颠倒世界拾取的物资，返回主世界后仍然在背包中。
-   玩家在颠倒世界消耗的弹药记录在全局背包数据中，返回后保持消耗结果。
-   玩家在颠倒世界受到的伤害会保留。
-   玩家在颠倒世界消耗的食物、水和医疗用品记录在全局物品状态中，返回后保持当前数量。
-   玩家在颠倒世界产生的体力、疲劳和SAN变化会保留。

玩家背包和角色数据由全局PlayerState统一管理，世界切换只更新所在世界层和坐标。

## 23.4 敌人数据不同步

敌人属于世界层专属实体：

  敌人           主世界               颠倒世界
  -------------- -------------------- ------------------------------
  普通丧尸       主世界丧尸生态       颠倒世界使用独立克苏鲁生态层
  特殊丧尸       主世界特殊丧尸       颠倒世界使用独立克苏鲁生态层
  T1观察者       可以按区域规则出现   可以出现
  T2异常潜伏体   可以出现             可以出现
  T3狩猎者       可以出现             可以出现
  T4高级猎食者   高污染区域出现       可以出现，权重更高
  T5领域守护者   固定事件或特殊区域   固定事件或特殊区域

主世界丧尸保留独立世界层状态；玩家进入颠倒世界期间，丧尸使用区域简化模拟，玩家返回后恢复对应活动状态。

两个世界按世界层管理敌人生态；跨越裂隙的特殊生物通过专属能力和事件配置实现。

## 23.5 时间同步

两个世界使用同一套世界时间。

玩家在颠倒世界停留期间：

-   世界时间继续流逝。
-   玩家饥饿、口渴、疲劳和卡路里收支继续计算。
-   主世界丧尸可以使用低频模拟更新。
-   主世界容器和建筑沿用共享实体状态，保留已搜索、破坏和交互结果。
-   颠倒世界敌人继续按照其世界层规则活动。

世界时间和玩家生存状态在世界切换期间持续推进，远距离区域事件使用低频模拟。

# 24. 裂隙生成与地块触发机制

## 24.1 裂隙生成条件

裂隙通过预设候选地块和动态触发条件生成。

建议满足以下任意一类条件后，允许区域裂隙系统开始工作：

**条件A：精神异常程度达到阈值**

-   当前SAN较低，例如低于35。
-   或异常关注度达到指定阈值。
-   玩家处于有异常活动记录的区域。
-   玩家附近存在合格裂隙候选地块。

**条件B：进入高等级感染区域**

-   区域污染等级达到3级或以上。
-   玩家进入该区域的有效探索范围。
-   当前区域存在裂隙候选地块。
-   区域裂隙刷新冷却已经结束。

SAN数值越低代表精神状态越差；裂隙生成权重由SAN受损程度、异常关注度和区域污染共同计算。

## 24.2 裂隙候选地块

使用地块标签和预设Marker提供候选点，由刷新导演按周期进行评分和抽选。

候选位置可以包括：

-   房屋外部地面。
-   地下室地面。
-   废弃道路。
-   森林空地。
-   医院和实验室周边。
-   高污染区域的建筑内部。
-   地下设施入口。
-   特殊遗迹附近。

候选点数据：

  字段                  作用
  --------------------- ------------------
  `rift_anchor_id`      裂隙候选点唯一ID
  `region_id`           所属区域
  `world_position`      主世界坐标
  `minimum_pollution`   最低污染等级
  `minimum_attention`   最低异常关注度
  `spawn_weight`        生成权重
  `rift_type`           裂隙类型
  `is_safe_for_spawn`   是否允许生成
  `cooldown_until`      下次允许生成时间

## 24.3 裂隙生成评分

建议通过综合评分选择候选点：

`RiftScore = PollutionScore + AttentionScore + SanPressureScore + AnchorWeight`

其中：

-   `PollutionScore`：区域污染等级贡献。
-   `AttentionScore`：异常关注度贡献。
-   `SanPressureScore`：SAN受损程度贡献。
-   `AnchorWeight`：候选地块自身权重。

候选点根据评分、生成权重、区域数量上限和冷却时间进入抽选流程。

## 24.4 生成限制

第一轮测试参数：

  限制项                                    初始建议
  -------------------------- --------------------------------------
  玩家附近同时可活动的裂隙                    1个
  单一区域活动裂隙上限                        3个
  裂隙与玩家初始距离                        8--30米
  裂隙生成冷却                         5--10分钟游戏时间
  安全据点内生成                    使用独立候选点与事件配置
  玩家附近生成                通过环境预兆、距离检查和触发流程呈现
  同一候选点重复生成                      必须经过冷却

裂隙在有效候选地块生成，并通过环境预兆为玩家提供观察和选择路线的时间。

## 24.5 裂隙出现的预兆

建议采用三个阶段：

  阶段       表现                                    时长参考
  ---------- -------------------------------------- ----------
  异常征兆   地面轻微震动、声音失真、SAN轻微波动      2--4秒
  裂纹形成   地面出现黑色裂纹、局部扭曲、微弱触须     2--3秒
  裂隙活动   裂口打开，触手开始活动                    持续

预兆使用多套视觉和音效组合，根据裂隙类型、污染等级和区域环境变化。

## 24.6 裂隙类型

  类型         作用                     特征
  ------------ ------------------------ --------------------------------
  微型裂隙     主要用于触发触手捕获     面积小、活动时间短
  稳定裂隙     可作为较稳定的世界通道   有明显入口和出口
  不稳定裂隙   短时间开放               可能关闭，需要尽快通过
  区域裂隙     连接高污染区域           可以作为特殊探索路线
  固定裂隙     剧情或特殊地点使用       通过地点配置和剧情事件保持存在

普通探索中以微型裂隙和不稳定裂隙为主，固定裂隙用于剧情、地下设施和Boss区域。裂隙外形类型不等于危险等级；R4、R5中满足特定配置的裂隙可以吞入车辆，见第81—83章。

# 25. 触手捕获、拖拽与世界切换

## 25.1 捕获流程

裂隙的触手不是装饰物，而是一套独立攻击机制。

推荐流程：

1.  玩家进入裂隙感知范围。
2.  裂隙判断玩家是否处于可捕获区域。
3.  触手从地面裂口伸出。
4.  触手短暂瞄准玩家。
5.  触手尝试抓住玩家。
6.  捕获成功后将玩家拖向裂隙。
7.  玩家进入挣扎阶段。
8.  若未能挣脱，则进入世界切换流程。
9.  玩家在颠倒世界对应坐标附近出现。

## 25.2 捕获条件

触手必须满足以下条件才允许抓取：

-   玩家处于触手最大伸展距离内。
-   玩家与裂隙之间没有完全阻挡的墙体或地形。
-   玩家没有处于不可打断的特殊动画。
-   裂隙当前处于活动状态。
-   当前裂隙没有达到最大抓取次数或冷却限制。

建议初始参数：

  参数                       初始值
  ------------------ ----------------------
  触手最大伸展距离           5--8米
  抓取预警时间             0.8--1.2秒
  拖拽持续时间               2--4秒
  单次抓取冷却              10--20秒
  触手基础抓取速度    由动画和物理测试确定

触手通过射线检测和碰撞遮挡确定抓取路径，并在抓取前播放明确预兆。

## 25.3 玩家反制

触手捕获需要保留有限的反制机会，否则会变成无法控制的强制传送。

建议提供三种反制：

  反制方式   作用
  ---------- ------------------------------------
  闪避       在触手抓取前离开判定区域
  力量挣脱   被抓住后消耗体力进行挣扎
  攻击触手   使用近战或枪械破坏触手，使抓取中断

力量有效等级提高挣脱效率，体力、腿部伤势和负重共同影响最终挣脱结果。

挣扎需要消耗体力。若角色体力过低、腿部严重受伤或处于超重状态，挣脱难度提高。

## 25.4 被拖拽状态

被抓住后进入 `TENTACLE_GRABBED` 状态：

-   玩家移动输入受到限制。
-   镜头仍然可以有限转动。
-   角色沿触手方向被拉动。
-   玩家可以执行挣扎或攻击。
-   体力持续消耗。
-   可以播放特殊受击动画和触手缠绕效果。

如果拖拽完成，进入 `RIFT_TRANSITION`。

## 25.5 世界切换

切换流程：

1.  暂停玩家普通移动输入。
2.  记录当前裂隙ID。
3.  记录玩家位置和朝向。
4.  找到该裂隙对应的颠倒世界出口锚点。
5.  切换当前世界层。
6.  更换环境、光照、材质和敌人集合。
7.  将玩家放置到出口锚点附近的安全位置。
8.  执行淡入或空间扭曲效果。
9.  恢复玩家控制。

使用同一份共享地图和碰撞数据，通过世界层切换完成主世界与颠倒世界切换。

## 25.6 进入后的安全落点

目标位置必须经过检测：

-   通过空间碰撞检测选择有效落点。
-   通过地面检测和导航可达性选择可行走位置。
-   落点优先选择具有安全距离的可行走位置。
-   使用实体碰撞检测避开家具、车辆和建筑占用空间。
-   应优先选择裂隙周围2--4米内的可行走位置。

当对应位置状态变化时，沿地面法线和导航可达点寻找最近安全落点。本节适用于徒步角色；车内整车被捕获时，必须改用第83章对整车占地和高度的安全落点检测。

# 26. 颠倒世界生态与返回机制

## 26.1 敌人生态

颠倒世界的敌人刷新池由克苏鲁生物构成，主世界丧尸使用独立刷新池。

  内容           主世界       颠倒世界
  -------------- ------------ --------------------
  普通丧尸       有           无
  特殊丧尸       有           无
  T1观察者       有条件刷新   可以刷新
  T2异常潜伏体   有条件刷新   可以刷新
  T3狩猎者       有条件刷新   可以刷新
  T4高级猎食者   高污染区域   更高出现权重
  固定型克苏鲁   特殊区域     可以大量使用
  区域型克苏鲁   特殊区域     可以大量使用
  T5领域守护者   固定事件     固定事件或核心区域

颠倒世界通过敌人分布、视线、区域控制和未知路线制造压力，敌人密度由区域等级、玩家进度和当前敌人数量共同计算。

## 26.2 颠倒世界的资源

物资与主世界共用数据：

-   已经被主世界搜刮的容器，在颠倒世界中同样为空。
-   颠倒世界中被玩家搜刮的容器，主世界对应容器也变为空。
-   玩家在颠倒世界拾取的物品进入同一个背包。
-   玩家在颠倒世界丢弃物品，物品会出现在对应共享坐标。
-   克苏鲁掉落物使用全局唯一物品ID，跨世界状态保持一致。

可以通过视觉表现区分物资状态，例如颠倒世界中的同一罐头表面腐化，但物品ID、重量、卡路里、饱腹感和数量不变。

## 26.3 返回裂隙

每个主世界入口裂隙都应具有一个对应的颠倒世界出口锚点。

建议使用配对ID：

``` text
rift_pair_id: rift_pair_0018

main_anchor:
    position: 主世界坐标

inverted_anchor:
    position: 对应颠倒世界坐标
```

玩家进入后，颠倒世界中必须存在至少一个有效返回裂隙。

返回方式：

1.  玩家找到颠倒世界中的裂隙。
2.  接近裂隙。
3.  触发返回交互或直接穿越。
4.  系统根据裂隙配对ID找到主世界对应位置。
5.  切换回主世界。
6.  在对应裂隙附近安全落地。

## 26.4 额外裂隙与空间路线

除了进入时生成的配对出口，颠倒世界还可以生成其他裂隙。

这些裂隙可以连接到主世界的其他候选锚点，形成跨区域路线。

例如：

-   从主世界医院进入颠倒世界。
-   穿过颠倒世界中的地下通道。
-   找到另一个裂隙。
-   从主世界工业区的对应位置离开。

颠倒世界同时承担高风险探索区域和跨区域路线网络的功能。

远距离出口由区域污染等级、特殊锚点和剧情条件控制。

## 26.5 防止玩家被困

必须设置防软锁规则：

-   玩家进入颠倒世界后，至少存在一个**人物可通过**的返回出口。车辆返程另需尺寸和质量合格的载具通道；见第83章。
-   如果出口被异常事件关闭，系统应在合理时间后激活备用出口。
-   如果出口锚点因建筑破坏而不可达，自动寻找附近可达位置。
-   如果玩家存档时处于颠倒世界，读档后仍然处于颠倒世界，并保留返回出口。
-   每次进入颠倒世界时写入有效返回出口，并在出口状态变化时更新备用锚点。

## 26.6 返回主世界后的状态

返回主世界时：

-   玩家HP、SAN、体力、饥饿、口渴和疲劳保持当前数值。
-   玩家伤势保持。
-   背包、装备和弹药保持。
-   技能经验保持。
-   世界时间继续推进。
-   主世界容器和物资状态保持。
-   主世界丧尸状态恢复或继续简化模拟。
-   颠倒世界敌人状态按其独立存档规则保留。

# 29. 裂隙、敌人与异常关注度的联动

## 29.1 三种独立参数

需要区分：

  参数           作用
  -------------- --------------------------
  SAN            玩家当前精神稳定程度
  异常关注度     异常世界对玩家的关注程度
  区域污染等级   当前区域的异常强度

三者分别保存，并通过明确的联动规则共同影响敌人刷新和裂隙生成。

## 29.2 裂隙生成权重

建议：

-   SAN越低，精神异常压力越高，裂隙候选点权重越高。
-   异常关注度越高，裂隙生成概率越高。
-   区域污染等级越高，裂隙更容易生成。
-   玩家在同一地区停留越久，候选地块权重可以逐渐增加。
-   已经生成裂隙的区域进入冷却，避免短时间连续生成。

## 29.3 颠倒世界敌人刷新

颠倒世界的克苏鲁刷新由以下因素决定：

-   当前区域污染等级。
-   当前异常关注度。
-   最高遭遇阶段。
-   玩家在颠倒世界停留时间。
-   当前区域的敌人数量。
-   固定型和区域型敌人的占位情况。
-   是否存在特殊剧情事件。

颠倒世界敌人密度根据区域等级、当前敌人数量、刷新冷却和玩家停留时间动态计算。

## 29.4 玩家停留时间

颠倒世界可以增加一个隐藏的 `InvertedExposureTime`：

-   用于控制特殊事件出现概率。
-   用于调整异常环境效果。
-   用于触发部分裂隙不稳定事件。
-   用于提高高等级克苏鲁的遭遇概率。

InvertedExposureTime作为独立世界层参数，控制特殊事件、环境变化和遭遇权重；SAN仍单独计算。

## 29.5 裂隙与敌人的关系

建议增加以下规则：

-   部分固定型克苏鲁守护裂隙。
-   部分区域型克苏鲁以裂隙为领地中心。
-   T4刷新点在区域内分散布置，并依据出口安全距离进行配置。
-   T5可以控制某个区域的裂隙开合。
-   跨越裂隙的克苏鲁通过专属跨界能力和特殊事件配置实现。
-   特殊剧情敌人可以拥有跨世界能力，但必须作为独立能力设计。

## 29.6 进入颠倒世界的风险递增

建议玩家在颠倒世界停留越久，环境压力越明显，但必须给出可读的预兆：

1.  初期：环境异响、远处轮廓和低频SAN压力。
2.  中期：异常生物活动增加，裂隙位置出现变化。
3.  后期：高等级克苏鲁巡猎，部分区域出现空间干扰。
4.  极端状态：特殊事件触发，玩家需要尽快寻找出口。

颠倒世界停留时间通过环境压力、敌人活动和裂隙状态逐步提高探索风险，让玩家根据路线和资源判断继续深入的时机。

``` gdscript
func can_spawn_rift(player, region, anchor) -> bool:
    if anchor == null:
        return false

    if not anchor.is_safe_for_spawn:
```

## 31.5 仇恨值计算伪代码

``` gdscript
func update_aggro(delta: float) -> void:
    if has_line_of_sight_to_player():
        continuous_sight_time += delta

        var sight_multiplier = min(
            1.0 + continuous_sight_time / 5.0,
            3.0
        )

        var gain_rate = base_aggro_gain * sight_multiplier

        aggro += gain_rate * delta
        aggro = clamp(aggro, 0.0, 100.0)

        last_seen_position = player.global_position
        last_seen_time = Time.get_ticks_msec() / 1000.0

    else:
        continuous_sight_time = 0.0
        update_lost_sight_behavior(delta)
```

## 31.6 速度计算伪代码

``` gdscript
func get_current_speed() -> float:
    var aggro_multiplier = 0.75 + 0.5 * (aggro / 100.0)

    var visibility_multiplier := 1.0

    match current_state:
        State.DIRECT_CHASE:
            visibility_multiplier = 1.0
        State.LAST_KNOWN_POSITION:
            visibility_multiplier = 0.65
        State.SEARCH:
            visibility_multiplier = 0.40
        State.RETURN_TO_TERRITORY:
            visibility_multiplier = 0.55
        _:
            visibility_multiplier = 0.5

    return (
        base_speed
        * aggro_multiplier
        * visibility_multiplier
        * creature_speed_modifier
    )
```

``` gdscript
func update_lost_sight_behavior(delta: float) -> void:
    lost_sight_time += delta

    if lost_sight_time <= last_position_memory_time:
        set_navigation_target(last_seen_position)
        current_state = State.LAST_KNOWN_POSITION
        return

    if not reached_last_seen_position():
        set_navigation_target(last_seen_position)
        return

    current_state = State.SEARCH
    search_timer += delta

    if search_timer >= search_duration:
        current_state = State.RETURN_TO_TERRITORY
        aggro = max(0.0, aggro - decay_rate * delta)
```

# 33. 双世界与高级AI验收标准

## 33.1 双世界同步

-   两个世界使用相同建筑坐标和房间布局。
-   玩家在一个世界打开门，另一个世界对应门保持打开。
-   玩家在一个世界打碎窗户，另一个世界对应窗户保持破碎。
-   玩家在一个世界搜刮容器，另一个世界容器同步为空。
-   玩家在一个世界拾取物资后，另一个世界对应位置同步显示已拾取状态。
-   玩家在一个世界丢弃物品，另一世界对应位置能看到同一物品。
-   玩家切换世界后，背包、HP、SAN、伤势和世界时间保持当前状态。

## 33.2 颠倒世界生态

-   颠倒世界生态层由克苏鲁生物组成。
-   主世界丧尸保留在主世界生态层，颠倒世界运行克苏鲁生态层。
-   颠倒世界能够刷新T1--T4克苏鲁。
-   T5只通过特殊地点或事件出现。
-   颠倒世界敌人使用独立实例ID和世界层存档，返回主世界时恢复原有实例状态。
-   主世界和颠倒世界的敌人状态能够独立保存。

## 33.3 裂隙系统

-   SAN或异常关注度达到条件时可以触发裂隙候选地块。
-   高污染区域可以提高裂隙生成权重。
-   裂隙候选点经过玩家距离、地形状态和环境预兆检查后生成。
-   裂隙出现前具有环境预兆。
-   触手抓取路径通过墙体和大型障碍遮挡检测。
-   裂隙具有抓取冷却和区域数量限制。
-   玩家能够通过对应裂隙返回。
-   出口失效时有备用返回机制。
-   存档读档后根据裂隙配对ID恢复入口、出口和备用锚点。

## 33.4 仇恨追踪

-   持续可见时仇恨增长速度递增。
-   仇恨值提高时移动速度提高。
-   失去视线后移动速度下降。
-   失去视线后敌人前往最后发现位置。
-   敌人使用最后发现位置和搜索系统更新目标。
-   到达最后位置后会进行搜索。
-   搜索失败后仇恨逐渐衰减。
-   玩家重新进入视线后敌人重新追踪。
-   光源感知能够使用同一套仇恨系统。
-   仇恨通过记忆时长、搜索时间和衰减速率回落。

## 33.5 固定和区域型敌人

-   固定型敌人主体持续锚定在指定位置。
-   固定型敌人可以通过触手和区域攻击威胁玩家。
-   固定型敌人的仇恨提高攻击频率、触手伸展速度和攻击范围。
-   区域型敌人能够在领地内部巡逻和追击。
-   区域型敌人按照领地边界管理追击和返回行为。
-   玩家离开领地后，敌人会停止扩大追击范围。
-   潜伏型敌人具有可观察的环境预兆。

# 81. 裂隙危险等级与车辆吞噬资格

## 81.1 形态与危险等级分开

第24章的微型、稳定、不稳定、区域、固定裂隙描述**外形/存在方式**；本章使用 `rift_threat_level`（R1—R5）描述**强度、抓取对象和能否吞没车辆**。两者独立：同样是区域裂隙，可能只有R2，也可能在高污染事件中达到R5；高级裂隙中也只有配有 `vehicle_capture_enabled=true` 的个体具备吞车机制。

| 危险等级 | 主要目标 | 载具捕获规则 | 预兆与应对 |
|---|---|---|---|
| R1 | 环境异常、弱触手 | 不抓载具 | 裂纹、轻微异响 |
| R2 | 徒步角色 | 不抓载具，车可作为临时遮挡 | 地面触手、局部低速拉扯 |
| R3 | 徒步角色、近距离建筑外个体 | 不吞整车；可轻度干扰车辆转向/轮胎 | 更强环境扭曲、短时抓取 |
| R4 | 徒步角色、轻型车辆 | **有车辆捕获标签**时可拖小轿车、摩托等 | 地面大片裂纹、路面吸引、多个触手 |
| R5 | 徒步角色、中大型车辆 | **有车辆捕获标签**时可拖SUV、皮卡、面包车和一定质量内货车 | 大范围地面形变、强拉扯、长时间警报 |

车辆捕获还需满足裂隙的 `max_vehicle_mass_kg`、`max_footprint_length_m`、`max_footprint_width_m`、`capture_radius_m`、牵引组规则、物理路径和通道有效性。货车、拖车组并非默认每次都能吞入；超过质量或体积限制时只允许发动机熄火、陷车、侧滑或局部车损，不能把超大车辆强行缩成小模型。R4、R5只是本项目危险等级，与克苏鲁T1—T5和区域污染0—4不能混用。

## 81.2 触发权重与出现位置

高级车捕裂隙更偏向高污染区、废弃高速公路、研究设施外围、夜间异常事件或特殊任务路线；普通安全据点内部不凭天气随机出现。生成评分结合区域污染、玩家异常关注度、候选点地形类型、最近事件冷却、有效道路宽度、世界时间和可逃生路径。车捕裂隙不得在任务强制过场、车辆生成瞬间或存档加载首帧无预告触发。

候选点必须验证道路/开放地形可容纳裂隙、触手与车辆转向空间；若通往裂隙的路径被不可破坏桥墩、建筑柱或地形完全隔断，不得远程拉穿实体。

## 81.3 车捕裂隙公平性

- 初次发生前有明显视觉/声音/仪表异常预兆，危险等级越高，越早可观察。
- 玩家可加速驶离、转向避开、利用桥墩和墙体阻挡部分触手、攻击抓取点或降低负载来挣脱。
- 对低级、处于转场状态或刚加载出来的车辆设置短暂保护；抓取成功也应完整保留车内物资与人物生命状态。
- 高级裂隙不能因为车辆油箱刚好没油就忽略玩家反制机会；停驶载具更容易被捕获，但需更长预警。
- 只发生一次**权威世界层切换**，不得同时运行两份车辆物理模拟。

# 82. 高等级裂隙抓车、拖拽与反制流程

## 82.1 裂隙—车辆交互状态机

`IDLE → PREMONITION → ACTIVE → VEHICLE_DETECTED → TENTACLE_EXTENDING → VEHICLE_LATCHED → VEHICLE_DRAGGING → PHASE_TRANSFER → EXIT_RECOVERY`。

抓取取消分支：`VEHICLE_DETECTED/LATCHED/DRAGGING → TENTACLE_BROKEN / OUT_OF_RANGE / PATH_BLOCKED / TIMEOUT → COOLDOWN`。同一事件ID不能重复进入PHASE_TRANSFER。

## 82.2 捕获过程

1. `RiftManager` 在R4/R5活动裂隙检测载具碰撞体/质量/大小/当前世界层及特征标记，判断处于感知圆内；优先警示而非瞬时定身。
2. 车灯短暂闪烁、无线电干扰、轮下裂纹蔓延、仪表异常和路面卷曲；高危险裂隙的预兆建议4—8游戏秒。驾驶玩家可继续转向和加速。
3. 触手从地面/路肩伸出，针对轮轴、保险杠或底盘碰撞锚点发起可见的攻击，必须检查遮挡和抓取路径。
4. 一到多条触手命中后建立 `RiftVehicleLatch`；对目标车辆施加**有上限的额外牵引力**，不直接覆盖车体位置。牵引力影响速度和方向，但保留玩家控制及车体惯性。
5. 玩家可打方向盘驶离触手最大长度、主动倒车、短时间增加发动机扭矩、让乘员攻击触手，或在安全条件下离车；车辆受损、轮胎抓地和满载质量共同影响挣脱难度。
6. 被持续拖至裂隙的“车辆捕获界面”时，进入短暂锁定；检查通道尺寸、全车乘员、拖车处理、相邻障碍和目标世界层安全落点。
7. 所有检查通过后执行**原子相位转移**：关闭该车当前碰撞与物理权威→保存持久状态与乘员座位→切换活跃世界层→移动整车到同坐标附近合法的目标锚点→恢复物理/相机/输入→重新激活目标层敌人生态。
8. 失败或超时则释放触手、恢复车辆自由控制并进入裂隙冷却；不可出现“玩家进入另一个世界、车和NPC留在原地但游戏认为仍坐车”的分裂状态。

## 82.4 车辆差异和反制公式

推荐用可调参评分，而不是简单“速度高必挣脱”。例如：

`escape_force = traction × available_drive_torque × driver_input_factor × wheel_condition_factor`；

`rift_hold_force = base_pull_force × active_tentacle_factor × rift_level_multiplier`；

`escape_progress += max(0, escape_force - rift_hold_force) × dt`，同时允许通过击毁触手节点直接减少 `active_tentacle_factor`。数值需要真实驾驶物理实测后校准；重车可能更难拉动但也可能在泥地陷车，不能把“越重越有优势”写死。车辆撞击、轮胎打滑、发动机故障仍执行常规车辆损害规则。

## 82.5 乘员中断和紧急离车

抓取初期允许按车速和车门状况正常停车撤离；牵引强度较高时车门可能暂时卡住，需要解除抓取或破窗。驾驶者紧急跳车会结算七部位跌落/碰撞伤害；NPC若有相应简单AI可执行惊慌或尝试下车，但不无条件瞬移。若玩家成功跳车而车辆被吞，车辆带走其余仍在车上的乘员，玩家继续留在当前世界；如果没有乘员，空车也可以被捕获并成为可在颠倒世界寻找的实体。

# 83. 车辆跨世界状态、乘员、拖车、返程与防软锁

## 83.1 共享状态与独立活跃层

为了同时满足第22—23章的**世界实体共用唯一状态**和“车辆确实被吞入颠倒世界”，车辆采用 `VehicleInstance` 唯一数据、`active_world_layer` 单一实际层、`world_position` 单一物理坐标。切换世界改变的是车辆实际参与物理碰撞、交互和AI感知的世界层；车辆在另一世界可显示非交互的“异常映像”，但**不能复制可驾驶车辆**。建筑、路面、门窗与家具仍保持原有跨世界完全共享；车辆是其中具有活跃层归属的移动实体。

| 车辆数据 | 跨世界规则 |
|---|---|
| `vehicle_id`、车型、外观改装 | 唯一、跨世界保留 |
| 坐标、朝向、速度 | 同一持久状态；相位转移时执行安全位置映射 |
| 发动机、油量、油路、油箱破损 | 唯一，不因穿越满油/归零 |
| 电瓶电量、零件健康、轮胎状态 | 唯一，世界切换继续耗电/损坏规则 |
| 后备箱、货斗、乘客背包 | 全局唯一库存和实例ID |
| 车门、车窗、车灯和警报器 | 唯一功能状态，环境表现可以覆层 |
| 乘员与座位预约 | 由同一个车辆转移事务处理，不复制NPC |
| 牵引关系、拖车库存 | 独立ID、可根据裂隙容量一起转移或断开 |
| 实际物理/交互层 | 只能是 `MAIN_WORLD` 或 `INVERTED_WORLD` 之一 |

## 83.2 乘员的世界层规则

玩家始终以当前座位为根对象，与整车在同一个事务切换层；玩家七项生存状态、SAN、感染、伤势、药物计时不暂停。**NPC默认不在颠倒世界自然生成或驻扎**，但**已实际乘坐该车并被同一次裂隙事件捕获的NPC**可以作为临时同行者被带入：原NPC实例从主世界动态实体池移至车辆乘员名单，进入颠倒世界后用低复杂度“留车/跟随玩家撤离/有限自卫/恐惧”行为；离开车辆时在目标层创建同一个NPC的活动节点，主世界不保留其可交互复制体。返回主世界后恢复岗位/任务关系；若同行NPC死亡，唯一身份记录持久保存。

这项同行许可是“被车一起拉入”的物理事件例外，不会让颠倒世界出现随机居民NPC、任务商人或据点守卫分身。

## 83.3 拖车和牵引组如何通过

- 裂隙需对主车和拖车**整组质量、总外形包络、连杆角度**进行认证。
- 满足R5的群体捕获规则时，主车、拖车及各自独立库存作为一个事务转移，挂接关系保留。
- 主车可通过但拖车不符合容量时，先播放挂钩受力警告；允许玩家在安全窗口解除挂接。若继续捕获，按事件配置断开挂钩：主车被吞、拖车留在原层，彼此 `tow_link_id` 清除；拖车与其货物仍是唯一实体。
- 禁止先把车切世界再逐帧拉拖车通过裂隙造成两层刚体互相牵引。分层刚体之间不能保持物理关节。

## 83.4 颠倒世界驾驶和环境

颠倒世界沿用相同道路、高度和碰撞布局，因此普通路面可以驾驶，但异常光照、腐化覆层与敌人生态改变体验。颠倒世界不刷新丧尸，只刷新克苏鲁；车灯可能激活部分T3/T4光感知，发动机普通噪声不令克苏鲁拥有原本不存在的听觉，但车辆的**存在、移动、直接碰撞、特殊异常感应**仍可使其锁定。高污染地点可增加局部异常阻滞或车窗视觉干扰；此效果必须明示，不可直接瞬间摧毁发动机。

若玩家在颠倒世界停下并离车，车辆保留在颠倒世界，位置和货物持久保存；玩家可以走远、通过普通人物裂隙返回，但不能要求已留在颠倒世界的车也无条件回主世界。若另一个世界显示车辆残影，该残影不可装货、开车、维修或被NPC拖走。

## 83.5 返回主世界

- 徒步返回继续使用第26章的**至少一个可达出口**保底；这个保底只对人物生存有效，不等于任意裂隙可供汽车通过。
- 开车返回必须找到 `vehicle_passage_allowed=true`、质量/尺寸匹配、可接近且当前有效的裂隙；稳定高等级裂隙和特殊大型通道优先作为载具回程路线。
- 车辆经过返程裂隙时走与进入一致的授权、动画与原子转移流程，保留全部物品、油量、车损和乘员。
- 地图与日志标记“人物可通过”“载具可通过”“本车体积/质量不适用”和已知通道方向，帮助玩家规划携车撤离。
- 如果玩家把车遗弃在颠倒世界，允许在任务中获取车辆回收信息并前往有效回程裂隙；不免费把车送回据点。玩家死亡或存档重载时同样保留车的位置与活跃世界层。

## 83.6 极端情况和保底

1. 目标锚点的共享建筑或地形被改造到不允许停车：从附近候选可驶入表面寻找整车合法落点并保留朝向，不能只检查玩家脚下2m的普通安全点。
2. 目标点在桥梁边、车库、车顶或水面：执行多点地面/坡度/上方空间检测；不满足则拒绝相位转移，触手释放并进入冷却。
3. 驾驶途中被捕获但玩家突然存档：记录 `pending_transfer_id` 与阶段；读档后要么完成整车转移，要么回滚到上一个合法驾驶位置，不能车和角色分离。
4. 车辆中途爆炸或毁坏：停止相位过程，结算残骸、货物和乘员，各实体归属清晰；不可生成两具车壳。
5. 车内NPC因任务变化被移除：先释放真实座位占用，再更改任务状态，不能保留隐形NPC碰撞体。
6. 车辆与拖车跨区装载：相关两个区块在事务提交前短时固定加载；成功后异步卸载旧层，不通过全世界扫描找实例。
7. 玩家成功徒步离开颠倒世界，而车辆仍在其中：可以在角色界面查阅最后已知车辆位置；人物不会被强制困住。
8. 相位转移时远距离据点电网与NPC继续按世界时间单次结算，不因为车辆进入新层重新生成据点物资。
