# 敌人生成/密度/尸潮：不依赖玩家转身刷新

## 1. 守恒的人口数据
每个`PopulationCell`记录`birth_seed`、`living_ids`、`active_ids`、`sleeping_groups`、`dead_ids`、`spawn_cooldown_world_time`、`last_noise_target`和`zone_id`。普通丧尸只从该人口池获得生存ID；既不能连续进入同一建筑凭空刷尸，也不能通过升级地图LOD而复活。

## 2. 生态分层
近区70m以内实体拥有完整感知、寻路、动画与碰撞；70—220m范围将AI更新降低到0.5—2Hz并简化碰撞；更远只保留群体数量、中心和行进向量。数值是性能起点，可按照CPU帧预算调整。`MAIN_WORLD`独立丧尸生态，`INVERTED_WORLD`不刷新丧尸，仅克苏鲁；克苏鲁生态按关注度/区域污染与五层T等级控制上限。

## 3. 生成资格与视线保护
候选锚点需检查：人口有存量、区域允许、存活ID未激活、玩家与摄像机不直接看到、没有刚清理保护、在导航有效位置、不会位于安全据点或道路车辆碰撞位置。屋内锚点以建筑的稳定RoomID存在，只在第一次附近激活时创建对应存活ID。不可在玩家眼前的空房间直接生成。

## 4. 生成决策

```text
FOR 每个激活PopulationCell:
  demand = min(cell.sleeping_count, cell.cap - active_count, global_cap - total_active)
  for n in 1..demand:
    candidate = 选择该zone的合法spawn_anchor(固定seed)
    if visible_from_camera(candidate): continue
    if player_distance(candidate)<min_spawn_range: continue
    if nav_is_unready(candidate): postpone
    enemy_id = reserve_living_id()
    enqueue_main_thread_spawn(enemy_id, candidate)
```

## 5. 声源与尸潮
NoiseBus声事件携带`origin,strength,occlusion,timestamp,layer_id,event_id`。人口池按道路/门洞门户可达距离重估趋近方向，高强度警报会把相邻区块的休眠群体拉向声源；群体跨块仅迁移`group_id`，并更新两个PopulationCell的归属。声源消失后按惯性和记忆超时逐步散开，不允许敌人永久读取玩家GPS位置。

## 6. 示例数据与验收
城区设初始密度每64m块20—45名的可调上界，森林1—5名；同块完整AI活跃数例为12—24，所有值要根据场景与性能重新测试。尸潮50人不应导致50次重复导航重烘焙。杀死同一个enemy_id后保存/退出/返回，该ID始终在dead集合，不再激活。
