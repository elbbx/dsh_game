# Codex 多对话框与模块接口计划

## A. 唯一接口所有权
- `WorldClock`：时间单例，只主架构M00发布tick；M01天气监听。
- `WorldRepository`：M23持有存档与状态事务；其余模块只以事件提交写操作。
- `InventoryService`：M04持有所有权和网格；M06提供ItemDefinition，不复制库存。
- `PopulationDirector`：M08负责总体人口预算；M09只管理已激活丧尸brain。
- `NavigationGateway`：M11拥有PortalGraph和导航查询；M10负责chunk创建/注销事件。
- `RiftTransferService`：M20统一管理车辆和角色跨层；M18不得自己随意切换vehicle layer。

## B. 每个Codex对话框开工流程
1. 在当前工程根目录阅读`AGENTS.md`、主合同、本模块设计书与原106章归属章节。
2. 向主集成对话框确认哪些字段已有实现，按文件列表提出变更计划。
3. 单个对话框只处理一个模块，并在独立`git worktree`分支写代码。
4. 先做数据格式与测试场景，再加可见资产或UI，最后做性能和断点读档测试。
5. 模块完成后生成测试记录、改动清单和接口RFC，提交到主集成对话框，按依赖顺序合并。

## C. Godot性能敏感任务次序
`M00 → M23 → M10 → M11 → M08 → M09 → M12 → M13 → M04 → M06 → M15 → M18 → M20`。UI/音频/天气/物品数值可在稳定接口后并行开发。建筑、载具和敌人数据表需由单一目录统一定义，避免各个对话框复制一份含义不同的“同名物品”。
