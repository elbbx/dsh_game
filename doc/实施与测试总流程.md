# AI 自主研发 / 验证 / 记录 / 续做闭环

## 每轮本地循环（单代理，持续执行）
- 读 `finished/state.json`→校验仓库和 Godot 版本→检查上次失败。
- 选下一个最接近完成“人能操作到”的功能，新增最小验收表。
- 先加失败用例或重现脚本，再修改 Godot 源码与数据/美术。
- 依次执行：静态资源与 JSON 校验→Godot 导入/脚本解析→场景 smoke→自动游戏逻辑测试→手动场景检查（如可图形操作）→重复进入房屋和存读档。
- 修复失败，不能删除失败测试蒙混过关；单项不通过不得登记完成。
- `finished/log.jsonl` 追加过程，`finished/state.json` 原子更新，完成表标记真实结果；立即继续下一个。

## 分层验收
L0 文件存在、PNG 尺寸/模式、JSON 可解析、禁止 3D 文件侵入 game。
L1 `godot --headless --path game --editor --quit` 导入、编译资源；进程退出码0且 log 无脚本 errors。
L2 `godot --headless --path game --quit-after 120` 主场景启动，至少 2 秒无脚本错误；L3 `godot --headless --path game --script res://tests/PrototypeChecks.gd` 验证场景内交互。
L3 Godot 测试场景或脚本自动调用进入/离开/搜刮/保存/重新加载；检查实体状态和资源守恒。
L4 图形运行手工验证像素轮廓、动画、真实操作、HUD、整合性能。
L5 导出 Windows zip/exe，干净电脑可启动，许可证报告和版本号一致。

## 缺少引擎/网络时
L0 可以 PASS，L1/L2 必须 `SKIP: Godot not found`，不能将 L0 当成已完成游戏验证。可继续设计与 Python 数据整理，但必须保留阻塞项，下一轮优先安装/配置官方 Godot 后真实跑起来。

## 测试日志/存档
日志写 `finished/reports/YYYYMMDD...json`，每次关卡变更保存输入序列/期望状态/实际状态/引擎版本/OS/提交hash。存档采取原子临时文件+校验+回滚（发布版本），错误时不覆盖最近可用档。打包前重测升级存档和老存档迁移。
