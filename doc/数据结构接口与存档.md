# 数据接口：2D 版固化约定

## 示例文件
`data/examples/building_instance.json`, `data/examples/room_state.json`, `data/examples/portal.json` 提供可转成 Resource 或 JSON 的示例。逻辑坐标一律 `cell: [x,y]`；不在游戏保存文件里混入 Godot Vector2 原生序列化文本。

## 名称空间
- `world:region:chunk_x:chunk_y`：大地图区块唯一ID；不受显示名称变化影响。
- `building:world_id:instance_uuid`：建筑实例ID。
- `room:building_instance_id:floor_id:room_id`：单个可进入空间。
- `entity:uuid` / `item_instance:uuid` / `container:uuid`：不会重用的动态ID。

## API
```
WorldSpaceManager.request_transition(portal_id, player_id) -> TransitionResult
WorldSpaceManager.restore_space(space_id) -> await SceneReady
SaveManager.persist_snapshot(world_id, player_id, state_delta) -> bool
PopulationDirector.activate_chunk(region_id, cell_rect) -> Array[EntitySnapshot]
NavService2D.find_path(space_id, start_cell, target_cell, actor_radius) -> PackedVector2Array
InventoryService.transfer(instance_id, source_id, target_id, rect) -> TransactionResult
AssetRegistry.get_sprite(asset_id, direction, frame) -> Texture2D
```
这些是产品层契约不是已经写好的 Godot 代码。实现必须做唯一ID、版本迁移、失败恢复、事务提交和事件幂等。

## 数据迁移
原 `data/items_original.json` 有 578 项，字段包括 `id,name,category,weight_kg,grid`；原 `data/recipes_original.json` 有 146 条，部分中文键。写一次可重复运行的转换器，输出 `data/runtime/items.json` `data/runtime/recipes.json`，报告非法 grid/缺材料ID/重复ID/材料负数/相互循环与原料超额；不能直接删条目掩盖错误。转换需保留ID兼容。

## 存档事务
写 `save.tmp` → flush+close → 验证 json/schema/校验和 → 与旧档轮换成 `.bak` → 替换为 `save.json`，平台文件更名注意跨盘失败。跨房屋的空间状态+库存+player位置作为一笔事务，必要时先日志后提交，重启检测未完成事务并回滚/重做；AI 应在 S2 完成它，而不能把示例的 FileAccess 直接称为成品级。

## 已提供的数据转换器
运行 `python scripts/normalize_data.py`，会生成 `data/runtime/items.json`、`data/runtime/recipes.json` 与 `data/runtime/import_report.json`；初始静态转换检出 578/146 条，错误 0。此步骤只做结构归一化，文本化效果仍需要转换成正式可执行规则，**不等于游戏内已实装 578 个物品或 146 个配方**。
