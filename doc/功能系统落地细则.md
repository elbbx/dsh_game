# 原功能系统向 2D 可执行机制转译

## 玩家状态（每秒分段更新）
`SurvivalStats` 纯数据：hp/hunger/thirst/fatigue/san/stamina/infection/cold/health，区分 0~100 正反向含义并统一命名，如 `hunger_need` 大则更饿。固定时钟负责统计，UI只订阅事件，不能让 UI 持有真实数据。存档需保存时间戳和上次统计值。每秒刷新 UI，耗血/耗体力视觉即时，状态超过阈值触发效果。感染仅增加风险，不直接致死，并保留医疗配方和抗感染机制。

## 装备、背包和物品
`ItemDefinition`(静态JSON)→`ItemInstance`(UUID、耐久、品质、装填状态)→`InventoryGrid`(格子、摆放矩形、负重/体积)。交换与拾取采用库存事务（预留→检查→提交），不允许资源复制。快捷栏引用背包实例ID，不能凭空生成物品；任一物品移动后失效引用要优雅降级。已发现的原始 items/recipes 不能直接无验证加载为 runtime 格式，应通过 normalization schema 与 report。

## 战斗
移动/瞄准/攻击由状态机和时间窗口驱动；近战命中用 2D ShapeCast2D 或自定义圆锥判定（和玩家屏幕方向一致）；远程采用 2D RayCast2D + tile occlusion、穿透表和声音传播。武器有独立 cooldown、装弹、弹仓、后坐力，动作与动画 hit-frame 同步。死亡从物理/AI/存档一致移除。

## 采集、制作与建造
2D 可采掘地格标记材质/耐久/资源，采矿产出按工具等级计算；树木使用 Sprite2D 替换状态、掉落木材、地图 diff。制造台是可交互 2D sprite + recipe service；电网是数据图结构。墙、地板、门、工作台摆放需 grid validity、碰撞与可到达检测。房顶只做完整的外部建筑像素图层；室内建造表现与室外可见外形之间通过建筑状态映射而非3D同步几何。

## 天气和卫生
天气按区域+时间产生雨雪强度，作用于移动/寒冷/发电/能见度/音源传播；2D 雨粒 CanvasLayer 或 viewport 粒子且像素对齐。淋湿、衣物耐脏、洗涤、疾病按事件/积分更新。不能用 3D 天空或 3D 贴图。

## 载具
`VehicleState2D`: 逻辑位置、转向、速度、车身方向帧索引、燃料、损伤、货仓、电源。玩家上车后变驾驶状态，视觉 2D 8向或16向像素精灵，与世界等距投影一致。载具碰撞使用 2D polygon shape；进入空间需明确 portals（大车不可随便进小房间）。

## 裂隙
使用`WorldSpaceManager` 在主世界与颠倒世界同坐标区域间切空间，事件只复制明确允许的载具/背包状态，持久实体ID隔离，防止在主世界与里世界各出现一份可收集物。SAN 更改敌人的渲染/行为数值，不建立3D幻觉场景。

## 任务与NPC
NPC 统一使用实体状态机，面对/路径/交易/战斗都用 2D 逻辑坐标；任务以事件标记进度，交付前检查库存事务、可存档和失败恢复。单人玩法为主，不实现多玩家队伍系统。

## UI
2D CanvasLayer 的 HUD 圆环、Tarkov 式物品格、6快捷分类、制作面板、地图、音量/按键设置；按数据事件驱动刷新、支持键鼠与不同分辨率。UI背景可以更高分辨率渲染但不得让世界像素产生拉伸/晃动。
