# 《加拿大死亡之路》式建筑独立空间：完整实现规范

## 禁止项
不要根据玩家遮挡降低房顶 alpha；不要让玩家在室外地图直接看见屋内家具；不要把屋内当作室外地图上隐藏的同一层 tile。街道上永远展示完整 2D 房屋正立面与屋顶。进入建筑只通过有确定门状态的入口完成。

## 数据对象
- `BuildingInstance`: `building_id`(世界唯一)、`template_id`、`region_id`、`exterior_anchor`、`entry_portal_id`、`door_lock_state`、`interior_seed`、`persistent_version`。
- `Portal`: `portal_id`、`source_space`、`source_cell`、`dest_space`、`dest_cell`、`entry_direction`、`lock`、`exit_cooldown`；双向链接需可验证。
- `RoomState`: `space_id`、被打开容器ID、已拾取物品ID、已杀敌ID、家具破坏、门锁、地上掉落物、当前NPC、上次模拟时间。每栋同模板的建筑**不能共享已搜刮标记**。
- `TransitionRequest`: `player_id`、`from_space`、`to_space`、`source_portal_id`、`dest_portal_id`、`snapshot_before`、`transaction_id`。

## 进入流程（原子性）
1. 玩家在合法交互范围（例如 1.35 格）且门可通行时，确认没有 UI 冲突/战斗硬锁；冻结输入和高危状态写入；记录室外 `(world_id, building_id, cell, facing, vehicle_link)`。
2. Fade CanvasLayer 淡出 0.12–0.22 s。必须抑制重复按门和新交互（transition_lock）。
3. 向 SaveManager 暂存转移事件；保存离开空间快照，释放仅表现节点但保留状态实体；加载目标室内模板、随机种子和已保存的家具、怪物、容器，恢复对象唯一ID。
4. 将 player 放置目标 portal 位置，冲突时在合法范围 BFS 搜索最近空地；设置 camera 当前空间 bounds，刷新 HUD/噪声/天气表现。
5. 原子提交位置+空间+库存状态，淡入并解除锁；如加载失败则回滚原外部空间及位置，展示错误信息，不丢失玩家或资源。
6. 离开屋内逆操作，目标为原门外安全点；确认出口被占时就近寻找合法 fallback，而不是把玩家塞进墙里。

## 楼层和大楼
多层建筑采用 `building#room_or_floor` 空间 ID；楼梯是 **2D 门户**，每层具有独立 2D TileMapLayer，可跨层寻路用 high-level portal graph；无需 3D 高度和 NavMesh。非活动楼层只存 state，不更新渲染，偶尔由世界时钟批量结算。

## 持久化/敌人
室外人口数量不是进屋后自动转化为室内敌人；进屋生成由固定房间种子与既存存档决定。掉落/敌人死亡/开门/家具容器内容必须落盘。离开又进入不得重复刷掉落。室外怪不能凭空跟随入屋；若设计为追门，则做明确的“门被撞开→跨空间转移”事件和延迟逻辑。

## 场景范式
```
ExteriorBuilding2D(Node2D)
  ├ BuildingSprite(Sprite2D)
  ├ DoorIndicator(Area2D)
  ├ CollisionFootprint(StaticBody2D)
  └ ShadowSprite(Sprite2D)
InteriorSpace2D(Node2D)
  ├ Floor(TileMapLayer)
  ├ Walls(TileMapLayer)
  ├ Furniture(Node2D y-sorted)
  ├ Portals(Node2D)
  ├ LootContainers(Node2D)
  └ Enemies(Node2D)
```

## 测试
必须覆盖：反复进出100次、门被锁、门外阻塞、空间加载失败恢复、离线存档重进、同模板双屋不串库存、进屋前后击杀残留、室内多层楼梯、载具仅允许通过设定门户、同时触发攻击和进屋的互斥。原型 `game/` 当前仅实现最简单淡入淡出+保存位置流程，完整事务与加载错误处理尚待 AI 开发。
