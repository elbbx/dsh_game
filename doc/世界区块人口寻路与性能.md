# 纯 2D 世界流送、敌人人口与寻路

## 空间
`SpaceId = overworld:region:chunk` / `interior:building_id:room_id` / `rift:realm:chunk`，每个空间使用逻辑2D网格；地图坐标浮点（实体）/整数（tiles）。空间间只有显式的 portal。

## 区块流送
建议 chunk=32×32 或 64×64 逻辑格；初期3×3活动圈，外围5×5压缩模拟圈（视 Godot 性能调整）。地图数据和实体状态分离：`TerrainChunk` 不可变地形+diff，`EntitySnapshot` 可变对象，`PopulationCell` 数量概览，`StreamController` 负责加载/卸载。异步生成线程只做纯数据，不直接改场景树；主线程逐帧限额实例化 tile/actor。摄像机裁剪、对象池、稀疏存档减少资源波动。

## 人口与刷新
以区块人口预算按地区/时间/事件变化，邻接区迁移遵守总量守恒；激活时实例化有唯一entity_id的样本，离屏卸载时汇总回人口与持久状态。新刷点避开玩家视野、近距离、刚搜过建筑与安全区；室内固定敌人由房间 seed + 状态决定，死亡ID不得再生成。

## 声光和丧尸AI
声波事件 `{space_id, pos, loudness, timestamp, source_id}` 以格网衰减（墙/门阻尼）；敌人状态 `idle → hear → investigate → chase → search → lose → idle`，仇恨累积递增，失视保留 last_seen 而非瞬间遗忘。异空间传播只经 door event 做折减，不跨地图直接感知。

## 2D 导航
- 室外：区域网格 AStarGrid2D / 自定义 HPA* 分层，动态围栏由局部 `set_point_solid` 或自维护占用网格更新。车辆也用 2D 车道图。
- 室内：本地 AStarGrid2D；门与楼梯 portal graph 决定跨空间的 route segments，敌人换场景需要显式状态机，绝不能在不同 room 直接 `move_toward`。
- 寻路阻塞按半径与实体体积（不要只测中心点），动态障碍支持代价和短时绕行。每帧限量更新，局部缓存，避免所有丧尸同时 A*。
- Godot 4 推荐新项目用 TileMapLayer，`TileMap` 已废弃；等距图形与逻辑坐标转换必须经过统一服务。

## 性能检查
测量：活跃实体数、每帧 A* 次数/平均耗时、TileMapLayer set_cell 次数、区块装载p95、室内切换p95、GC/脚本分配和RAM。初始目标：60fps，首段可玩区连续探索10分钟不泄漏，不因进入室内重复加倍敌人数。不同PC基准须存机器配置，不能虚构。
